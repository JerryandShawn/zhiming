# 整理v2接线与盲评协议

新增`organize/v2/`；旧整理引擎、来源校验、changeset与撤销逻辑均未改。v2只产生归区/话题候选，不能自动应用真实历史。当前源码状态、冻结hash与最终指标见Q5回执；开发分数不能代替盲评。

## 分类与待整理

`classifier.LocalClassifier(settings).classify(text,context=None)`使用7区人工词表、字符2/3-gram和有限上下文平滑。canonical区ID沿用旧DEFAULT_SPACES，命理研习为metaphysics。`Prediction.area_id=None`表示待整理，waiting为真；不把无法确定的内容强塞日常。

`ClassificationContext`显式传前次预测、置信分与近期文字；无ambient会话状态。短承接句可沿当前话题，明确换题或新领域强证据应切换，无法确定就弃权。confidence是规则分数，不是校准后的真实正确率，不能据其直接自动应用。

文本核心不认证来源。主线入口应先用现有SourceGuard/当前消息投影核验撤销、revision和原话，再调用`scoped.classify_message(message,scope,context)`。OrganizeScope绑定owner/subject/thread；ScopedContext必须相同scope；非active、无痕、非persistent或assistant消息不进入持久整理。这个scope相等检查不能代替数据库中的当前来源授权。

## 话题候选

`topics.cluster_messages(messages,predictions,scope,similarity_threshold=.4)`复用旧TopicClusterer，改用本地字符向量，保持区与待整理分开。每条用户消息一个segment，返回Topic候选，ID含scope。主线长历史可先用既有切段模块；本适配器未改原切段逻辑，也不承诺一条多话题长消息的细粒度切分。

话题聚类只接原消息、其真实线程元数据与本分类器自己的Prediction；不能把expected_topic或盲评context_group当聚类标签。评测中的区标签ARI与话题ARI分开，不能拿区分对了冒充话题聚好了。

## ONNX端口

`onnx_port.OnnxEncoderPort()`默认关闭，不读环境变量、不读模型文件、不import runtime、不下载模型。即使OnnxConfig有路径，也必须host显式activate(factory)才访问注入encoder；无路径绝不调用factory。所有本轮测试只注入合成encoder。

输入批次、维度、有限数值严格校验；provider自定义异常转换成固定安全错误并禁用端口，避免泄露输入或路径。KeyboardInterrupt/SystemExit不吞。实际ONNX模型安装、加载、归一化和真实语料验证不在本轮范围；不能把端口测试称为模型已可用。

## 评测隔离与口径

开发可见旧600和新独立322合成集。B231在产品实现前已冻结；调参者不看B正文、标签、分布、评分或误例。命名映射study→metaphysics先于调参冻结，只换ID，不改语义真值。

`tools/eval/mod_organize_v2_eval.py`的prepare只读源码、参数、固定映射与评测器，生成外部SHA锚，不打开B。final必须核对锚、整树/参数/评测器与helper，排他取得一次性claim后才读B。候选冻结后不再调参；失败如实保留，后续若需新版本，必须另备未见过的盲集，不能重复刷B。

指标列出总数、已归类/弃权数及分母。assigned_accuracy保守把真值不明确但强行归类的样本计为未证实正确；另给原B manifest约定的明确样本assigned_accuracy_clear。不归类比例按全量计算，不能只挑明确样本。ARI同时区分all诊断与clear主口径；话题ARI独立使用expected_topic，只在预测完成后计算。

最终目标为已归类准确率≥85%、全量弃权≤35%；没有目标达标前不宣称整理质量已验收。合成盲评也不证明真实历史可自动整理。最终报告只聚合指标，不给调参者B误例反馈。
