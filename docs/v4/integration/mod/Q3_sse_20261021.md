# SSE v1纯核心接线说明

本轮新增`mingjing_core/streaming/`。这是服务端可调用的纯逻辑及注入存储端口；没有HTTP路由、真实PG连接或客户端改动。来源为28号冻结事件契约v1，以及主线`f307231dfd3e370cc6a534e6de2d234696fb5ef9`发布的JSON Schema；精确副本与测试证据在`docs/v4/evidence/MOD_2026-10-21/`。

## 模型和编码

`event_models`提供`RunScope(owner_id,run_id)`、`EventDraft(type,payload)`、`RunEvent(run_id,seq,ts,type,payload,v=1)`、`make_event`和`event_data`。payload深冻结；schema禁止的未知键、布尔冒充整数、非有限JSON和重复键会拒绝。内部时间UTC，wire ts始终+08:00，不依赖机器时区。

`codec.encode_sse/decode_sse`处理一个完整frame，id/seq和event/type一致；正文里的换行留在JSON字符串中，不能注入SSE头。主线Schema校验对象为`{"type": event.type, "data": event_data(event)}`；type在SSE event头，data内部是扁平公共字段与payload。不要把owner放到wire或将整个私有事件写日志。

final写入必须core4.0，事件message_id和envelope.message_id一致；usage与PublicReceipt按实际Schema键过滤。历史reader明确区分旧core3与core4，解析成功不证明原信封来自已提交事务，更不授予投递权。

P5内部updated/merged不是冻结memory_receipt事件的write_status枚举；真实提交成功后可发saved并在summary说明更新，原始业务状态可留符合PublicReceipt的信封receipt。proposal发pending_confirm；尚未提交的计划不能发saved。工具receipt的公开元数据与完整私人服务回执是不同投影。

## 存储和补发

`MemoryEventStore(clock=...)`用显式锁实现进程内原子append/operation幂等，适合离线测试。`append(scope,draft,operation_id=...)`分配seq并返回原事件；同操作不同内容冲突；重放保留原seq/ts。

`replay(scope,after_seq=0,limit=1000)`返回events/next_seq/has_more。seq可能有其他run的间隙，只要求递增，不能按连续号补造事件。Last-Event-ID必须在当前owner/run中验证；unknown与foreign统一不可用，不透露其他owner事件是否存在。metadata只给清理所需字段和指纹。

`PgEventStore`仅接收注入事务factory，没有SQL驱动连接。默认EventColumns映射本树真实表的`owner/run_id/seq/kind/payload/created_at`；现表seq不是bigserial，也没有operation_id列。主线必须实现run锁、当前授权/运行lease断言、序号分配、稳定操作账本、row写入和事务内NOTIFY；不能假称本端口拿来就能连接旧表部署。type/data仅显式可选列映射。

同事务顺序为锁run→校验当前运行权→幂等查重→分seq→写row/ledger→NOTIFY→提交；失败必须回滚。每次读取仍校验scope/run/seq及wire公共字段。纯fake验证不能证明真实PG锁或RLS生效。旧worker是否仍能emit由主线当前lease/fence验证，不由内存store授予权利。

## 合并、修订与心跳

`coalescer.DeltaBuffer(scope)`是不可变缓冲；feed_delta显式传generation与Clock。默认累计40字或从首字起150ms发出text_delta；运行循环须每约150ms调用poll_delta，空闲时不能等下一个模型chunk才检查。结束前flush_delta。单个大chunk按协议最大正文长度拆开，文本不丢失。

`replace_text`丢弃尚未发出的旧缓冲、generation加一，只产生text_reset。旧generation写入拒绝。revision_id为opaque标记，不按字符串大小猜版本。纯函数不能阻止主线把旧state再拿去发送，实际应用必须在当前run lease和generation CAS中提交输出。

`text_projection.reduce_event`对delta追加，对reset替换全文，旧seq不回滚，同lastseq异body冲突，final以权威信封text收尾。ask_user后停止新生成，但允许review/final后处理。主线runtime仍须停止模型循环；store只校验事件结构，不负责这一业务决定。reducer的scope必须来自已认证事件流，wire本身没有owner签名。

`heartbeat.heartbeat_tick`在15秒时产生`: ping\n\n`注释，不写库、不分配seq。调度tick由主线HTTP协程负责；本模块不启动后台网络任务。

## 24小时保留计划

`cleanup.plan_delta_cleanup`只基于主线已提交事务的CommittedRun生成计划，时钟从committed_at起算24小时，恰好到期可选中。store.metadata可直接传入；metadata_for_cleanup将存储fingerprint规范为清理引用，不读取正文。

仅选择当前scope、seq≤final_seq的text_delta，保留final、text_reset、工具与回执等。计划携带提交revision、seq和payload指纹供主线执行前CAS复核；本模块不执行delete。清理后如何保留游标归属tombstone、从已提交信封生成恢复视图，需要主线补发端接线；不能把不存在的游标默认为任意owner可读。delta保留策略不等于来源撤销或隐私删除，后者仍由独立遗忘传播完成。

## 尚未验证

没有真实HTTP断线/反向代理缓冲/PG并发/NOTIFY/多进程重启/真实运行lease/飞书接线验收。主线需修改既有run事件repository、runtime finalization、SSE路由与前端投影；本线未动这些已有文件。测试、性能和CI状态分别在日报/Q3回执中记录，不能将本地pure/fake全绿当整套P4上线完成。
