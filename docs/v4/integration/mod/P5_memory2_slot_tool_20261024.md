# memory_write 可选槽的安全接入边界

2026-10-24T03:42:38.406049+08:00

`MemoryWrite.slot` 已进入真实工具 schema，ID/别名由现有槽表校验，未知值视为不填。没有槽、null 或未知槽时，序列化仍保留全部原默认字段且不加入 slot，兼容旧日志指纹；有合法槽会改变指纹。模型工具 schema 已变化，因此不能复用旧候选的供应商等价性证明，本线没有发送探针。

初次普通低敏写入可以保存槽元数据并通过原生 Agent 的 saved 提交证明；multi 槽可并存，同槽完全相同原话仍走真实去重/撤销记录。不同槽不会误合并。临时出差、假设或与槽线索不符的原话不能写成长期城市槽；槽不会从文本自动推断或补到旧事实。

同一 single 槽已有当前值时，新值替换仍不开放。工具在实际新增事实之前返回 needs_confirmation/slot_update_requires_commit_proof，保持旧值及其版本，不同时写两条当前值，也不把更新谎报为 saved。旧未贴槽但词面可能属于该槽的条目只作歧义守卫；不会自动贴槽/选更新目标。已有的精确偏好冲突仍走同一 P3 proposal，提供 slot 不能关闭它。敏感资料仍先产生真实 P3 pending，不把模型槽参数当保存授权；确认与替换可由上一篇原子组合服务接线。

仍需主线：严格 updated 回执的实体/旧新链/操作证明、对外事件 v1 的状态映射及认证动作接线；参见 P5_slot_receipt_coordination_20261023.md。此边界没有动 Agent 循环、commit gate、渠道或模型层。解除守卫不能只删一段 if 后把所有 updated 当 saved。
