# P9 官方协议候选接线（26号核实后的新增入口）

此版本只生成JSON与状态转换，不访问飞书、服务器、数据库或模型。旧`cards.py`、旧CardKit与旧Outbox入口不改；主线需显式选择新入口并在真实权威事务内接线。协议依据为大脑26号核实记录，不是本线实际平台验收。

## 已独立验证的构建器

`mingjing_core.adapters.channels.cards_official_v3`保留answer_card、question_card、memory_receipt_card、proposal_card、followup_card、brief_card、route_card七类typed调用；复用只读cards_contracts。`validate_card`返回隔离JSON副本，拒绝非法JSON、重复元素/操作token、超过四按钮或一个主按钮、非法element_id及超限body。`card_sizes`同时返回内卡与最大finalize请求的UTF8字节数。

全部卡片配置`update_multi=true`。流式占位正文非空；不以官方尚未说明的“空markdown”行为做前提。回执必须由真实写入结果传入，builder不写数据，也不把pending/rejected冒充saved。跟进的敏感预览继续走既有safe_preview，正文权限应由主线另行核对。

字面字段从原typed输入逐字符转义，使用26号转录的数值实体及`&sim;`；不能先调用旧builder再反转反斜杠。`&`与`|`额外实体属保守工程策略，须stage核实。模板本身的Markdown格式保留；回答正文应来自已核验的可信产物，不把任意模型字段当操作/回执。

预算为工程保守值：内卡≤28000十进制字节，最终嵌套JSON wire≤30000字节，body组件树≤200。属性对象不重复算成组件。完整请求中JSON字符串会再次转义，不能只量内卡。大回答/依据采用摘要；大晨报按预算缩短正文并明确提示“内容已缩略，完整内容见明镜台”。链接由可信host传入并做host allowlist；本模块只做HTTPS结构校验。回执、状态和操作不静默移除；强制内容仍超限时拒绝。

## 官方状态机候选（正在独立验收）

新增`cardkit_official_v3`的prepare/claim/begin_dispatch/settle/reconcile/restore与namespace合并，只是可供主线事务驱动的纯入口。本接线文档不代表该阶段已完成全部恢复验收，实际结果见本阶段回执。

关闭必须分两步，分别拥有operation_id、wire UUID、seq和ACK：先PUT完整最终卡，再PATCH settings关闭streaming并更新summary。只有两步都确认才closed。最终内容已确认而关闭被拒，不能再发纯文本；未知结果不重发、不换卡、不改business key绕过。空text/reset产出noop_empty，不发PUT空content，也不宣称远端旧文字已清空。

seq为1..2147483647；内部operation_id保留，wire UUID取其SHA256前40字符。create无wire uuid幂等保证，未知create不得自动重建。旧Q6本地seq候选没有int32上限，必须经新官方wire边界再校验。allow_sequence_gaps默认True只是显式工程策略，官方未说明；200810/300317按明确规则新seq，不借一般重用策略越过未知状态。

每次claim与dispatch都要在权威事务内重新读取当前owner/subject、完整来源manifest/epoch、成功run、完整validation payload及当前渲染产物。实际wire的正文/最终布局必须绑定该产物；schema parse、旧缓存状态或自行构造的ArtifactEvidence不是授权。当前Q6门禁只支持已完成成功run，不能据此声称已授权运行中草稿流。

`reconciliation.cardkit`与official_v3子树采用双CAS合并。主线旧writer若整块替换reconciliation仍会抹掉证明，必须改主线已有writer。主线还需PG租约/fence/事务、持久化意图后再传输、恢复后对账，不可把内存对象当持久化证明。

## Host路由与错误处理

create POST `/open-apis/cardkit/v1/cards`；元素更新PUT `/:card_id/elements/:element_id/content`；finalize PUT `/:card_id`；关闭PATCH `/:card_id/settings`；发送卡片实体POST `/open-apis/im/v1/messages?receive_id_type=open_id`。JSON字符串字段与UUID/seq按26号逐项校对；传输前再量最终wire。

10002参数拒绝、200740不存在、200750过14天、200860超限、300302缺update_multi、300311跨app均不可盲重试。200770 UUID冲突为uncertain，不能换UUID洗掉；200810交互更新和300317序号过小要求新seq；200850/300309需要host决定reopen/finalize；网络/5xx/300120为unknown待对账。429/99991400仅在明确未执行时按reset秒数延后。关闭失败的一次重试只是显式策略意图，永久参数错误不能靠自动循环解决。

租户token由主线缓存，2小时有效、余量小于30分钟刷新。发送230049为unknown；230020/429延后；230053/230013/230038/230028永久拒绝，230053停主动发送。此处只记录接线，不改旧Feishu适配器、不读token。

长连接优先。Webhook应在反序列化/解密前校验原始body的EncryptKey签名，再由可信host校验app/chat/message/event身份；3秒内HTTP200，不返回3xx。三类token严格分开：K3业务action token、平台event.token、Webhook header.token；不得互作授权。平台延迟token是在响应后30分钟内最多两次，不能套用业务24小时/15分钟TTL。普通JSON卡与CardKit实体卡的响应策略按26号分别处理，toast不证明完成后续更新。
