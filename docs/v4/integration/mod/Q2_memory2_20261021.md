# 记忆2.0纯模块接线说明

本轮候选使用新增`memory2/`、`memory/slots.py`、`memory/retrieval*.py`。没有改`application/memory.py`、policy、数据库、HTTP、ContextEngine或工具入口；不代表完整P5验收。源码与测试状态以本轮日报/Q2回执为准。

## 入口与信任边界

| 新增边界 | 用途 | 主线必须提供 |
| --- | --- | --- |
| `memory2/contracts.py` | 不可变MemoryScope/Source/SourceAnchor/Fact/Snapshot | 已认证owner/subject、当前来源原文/版本/撤销状态、数据库revision与source_epoch |
| `memory2/sensitivity.py` | 分类和save/proposal/stop/reject/profile_confirm决策 | 原话锚点、owner设置、当前Clock；确认动作绑定的来源/版本/quote fingerprint/类别 |
| `memory/slots.py`、`memory2/mutations.py` | 同槽更新、去重、冲突提案、可撤销计划 | 稳定operation_id、可信snapshot；不要从模型提供的JSON直接拼授权快照 |
| `memory2/scoring.py`、`reflection.py` | 重要度/180天衰减、8节画像提案 | 当前有效事实、已编辑/置顶条目、可信带c/r依据的命理摘要 |
| `memory2/archive.py` | C2显式事件结束/有效期到期的归档计划 | 当前Clock、当前来源；只产生计划，不删除数据 |
| `memory/retrieval.py` | 同过滤的全文/向量融合 | 候选SearchUnit、当前SearchSource、归一到0..1的注入向量分数；未配置向量传None |
| `memory/retrieval_rounds.py` | 一轮用户+紧随助手的检索、助手建议note、撤回传播计划 | 消息稳定ID/版本/会话、当前source_state；主线finalize只生成assistant_claim note |
| `memory2/event_time.py`、`retrieval_projection.py` | U4双时间候选与检索投影 | said_at必须等于原话时刻；使用同一事务中的snapshot/clock |

纯函数不查询数据库。主线应在现有owner事务/运行lease内取snapshot、校验来源epoch与expected_revision、再应用plan并保存operation记录；提交前再次读取授权状态。旧快照无法证明当前数据库仍未撤销。内存apply/undo的通过不能代替PG并发、RLS、触发器和一次性action token验收。

`apply_plan`的Clock=None只支持重放同一个离线计划；生产适配必须传真实Clock。ChartSummary.trusted与现有ProfileItem必须来自按scope认证的应用投影，不能让模型JSON自行授予trusted或传入别人的条目。命理别名本身不是签名，主线还须验证它对应的真实chart/rule结果。

所有正文/原话/值/完整快照只供私有业务使用。不要把dataclass、`.as_dict()`、proposal文案或异常上下文整包写公共日志/追踪。给用户的错误由主线翻译成中文，内部reason code不带正文。

## 决策顺序

先认证scope与连续原话区间，再判断撤销、无痕、用户拒绝、密钥与出生资料流程。敏感规则和模型hint取较严；本次明确拒绝优先于类别长期授权。未知hint保守要求确认，不能靠把unknown加入设置绕过。每条敏感提案的问题key包含来源版本和原话fingerprint；已问过只返回待确认，不再重复提问，不把“问过一次”当作已同意。

`save`是允许写入的计划决策；只有主线真正提交成功的receipt才能说“已保存”。同槽更新必须经过相同策略；确认前不得覆盖旧值。模型给的slot按12项registry校验，未知忽略；短期出差/暂住不覆盖常住城市。无法确定的高相似反义只产出“以前你说……，现在说……，以哪个为准？”提案。

Undo需要稳定操作记录及完整before/after；并发变更不能被旧undo悄悄抹掉。原话撤回后，不得借undo、去重合并、置顶或历史链复活来源。忘掉链头/链尾后的修复是条件计划，主线仍需在事务中执行遗忘传播。

## 检索与时间

`search(owner,subject,query_tokens,kinds,limit,since,until,*,units,source_state,vector_scores,config,at)`先统一验证scope/source revision/撤回/无痕，再做`[since,until)`过滤。事件按event_at、其他按said_at；向量开关不改变过滤集合。融合默认0.6向量+0.4全文，纯全文退化不需要ONNX下载；时间命中乘1.1，显式at才启用180天衰减，goal/constraint不衰减。

SearchSource的role/origin必须取真实消息行；构造默认只方便合成user场景，不可替代数据库字段。伪造unit.origin=user仍不能把assistant来源提升为用户fact。round引用按user、assistant顺序绑定各自版本；别名只能是m系列，同一返回集中不重复。

默认只检索当前有效值；需要历史时显式include_history并保留valid=false。别名`〔mN〕`必须映射返回unit的source_refs。round和assistant_claim只能说“我上次说过”，不能说“你说过”；assistant_claim的kind是note、inferred=true，构造为用户fact会拒绝。

`absolute_event_candidate`使用来源原话及said_at调用唯一U4入口，不从模型摘要猜日期；保留原文，只有唯一非周期且无歧义结果才产出带event_at/event_end的候选。已有绝对日期冲突时要求确认。它不存储、不排程。画像反思和到期归档也只返回提案/计划；日期不明不能猜结束，用户编辑/置顶的画像条目不由后台覆盖。

## 主线接线及尚未验证项

主线后续修改旧`application/memory.py`与tool dispatcher统一v4写入策略，在既有`mutation()`中持久化新增计划；v3继续原策略。新增0009迁移/API/proposal队列/撤销token/Outbox receipt/ContextEngine L2/L4/异步索引和遗忘传播由主线完成，本线没有修改这些文件。

本轮不下载ONNX、不连接PG、不生成真实模型提案、不在stage跑legacy dry-run。全文分词复用现有jieba；测试与基准的TEMP/TMP落本树private，依赖已有Core环境。脚本模式全项目、真实质量≥85%、数据库assistant事实计数、浏览器回执和端到端投递均不由纯模块测试证明。
