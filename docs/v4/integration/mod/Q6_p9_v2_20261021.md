# P9 K3与流式Outbox接线候选

本轮仅新增纯策略与状态转换；旧action_tokens、CardKit、Outbox、PG入口均未改。真实飞书字段与调用顺序仍“待对照飞书官方文档核实”。测试仅FrozenClock、合成资料、替身，无真实调用。

## K3入口

`action_token_policy_v2.K3TokenService(store,clock=...,lookup=...)`复用旧service的签发、hashed capability、稳定operation_id和原子consume。主线路由必须把已认证的实际动作作为kind，不能用卡片外观类别代替动作。question/decision/memory_receipt/brief为24小时；delete_memory/delete_source/apply_organize为15分钟；未知kind拒绝，不接受客户端ttl覆盖。

`issue(**claim)`返回旧IssuedActionToken；`consume(raw_token,**claim)`返回TokenClickResult。只有其should_execute为真才可请求实际动作，之后还须主线核验当前来源/实体并按稳定operation_id幂等执行。重放不重复执行。

lookup必须查真实、当前、完整绑定的metadata；错误owner/subject/open_id/kind/entity/fingerprint、未知token、撤销或存储异常均返回统一无效错误，不泄露是否存在或过期。仅正确绑定且真实过期返回refresh_needed与“这张卡已过期，我重新发一张”。这只是刷新意图，不代表已发送新卡，不执行原动作。

MemoryTokenMetadataLookup只用旧store公开snapshot，持本地guard使本实例撤销不穿过lookup/consume。它没有PG持久原子性；正式接线必须在同owner事务中读metadata、查撤销/实体、consume并保存effect。不得让旧路径绕过新guard，也不得用内存结果宣称生产撤销已完成。

新wrapper不将旧15分钟question token追认为24小时；旧default未改。兼容层复用旧token digest/operation helper，升级旧service时要复核这两个内部入口。Clock在metadata lookup/guard之后读取，延迟至过期边界时不能使用进入函数前的旧时刻执行。

## 流式意图与租约

`stream_outbox_v2`以StreamScope绑定owner/subject/outbox/run/business/channel/target，StreamIntent绑定operation/kind/payload fingerprint与序列；所有状态转换产生新StreamState，host用行revision/fence作CAS。

领取前查权威成功run、完整已校验结果、完整依赖与原话状态；发送前再次查。FreshnessEvidence是可信host的事务一致性投影，不能由模型、浏览器或卡片回调构造；纯模块只核对一致性，无法认证PG是否实际被查。core4 envelope通过schema parse本身绝不是发送授权。

host必须先持久化dispatched意图再调用transport。只在尚未dispatch的租约到期后允许重新领取；任何已dispatch、超时、异常或状态未知都不能自动重发。不能换business、目标、新卡绕过去重；恢复已dispatch状态转uncertain，同一张卡续写。

lease token、fence、revision、到期端点、scope与op都匹配才可续租/回执；metadata仅存token摘要。旧worker或迟到ack不得覆盖新状态。update/close sequence保持单调，close未知不触发fallback；只有确定拒绝的close才能提出fallback意图。

## reconciliation.cardkit命名空间

`cardkit_reconciliation_v2.ReconciliationBinding`与StreamScope七字段一致。`merge_cardkit_reconciliation`接当前reconciliation、当前/预期行revision、预期namespace fingerprint，以及StreamState或旧CardCheckpoint，返回ReconciliationMerge计划。

只更新cardkit.stream/checkpoint，保留顶层delivered/evidence_ref、其他writer及cardkit未知siblings。绑定不可变、版本/序列不回退、unknown不能直接回可发送状态。相同patch是no-op；旧schema明确拒绝覆盖，需主线单独迁移适配。结果.as_dict返回独立拷贝。

此merge不会执行SQL，也不会核验发送授权。主线应在锁定Outbox行后取当前值、核验两层CAS并更新相应namespace。既有`adapters/delivery.py::reconcile_delivery`整块替换reconciliation，`prepare_delivery`部分路径也会清空；正式接线必须将这些既有writer改成保留命名空间的事务更新。仅调用本纯函数而继续保留旧整块覆盖，会丢失流式状态。

旧CardCheckpoint在有pending时恢复为uncertain；namespace仅验证并保存原metadata，不能把验证时得到的恢复投影当已执行对账。纯计划返回next_row_revision，由主线实际持久化成功后才可继续；CAS失败重新读，不能对发送未知状态盲目重试transport。

## 主线需要修改的既有入口

- 卡片动作路由：从可信会话/用户绑定取得全部claim；接K3 service，区分invalid与正确绑定的过期刷新意图。
- Outbox领取与发送：接完整来源/依赖权威事务、稳定operation、row revision/fence；先存意图再发，未知保留。
- PG所有reconciliation writer：命名空间安全合并，禁止整块覆写cardkit；补并发、崩溃恢复与旧worker实库测试。
- CardKit适配器：把新状态映射到旧同卡checkpoint与替身transport；正式外部字段要先核对官方文档。
