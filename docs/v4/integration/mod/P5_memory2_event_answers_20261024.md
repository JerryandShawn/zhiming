`MemoryEventAnswerService(memory, clock=...).confirm(owner, subject, gap_id, expected_revision=..., message_id=..., operation_id=...)`：认证调用方明确选择一个知识缺口，传入实际当前用户的答复原话ID。服务校验人物/事项、原事实版本、来源/敏感授权及撤销账本；答复必须晚于缺口、不在未来且在同一长期线程。仅接受纯单点日期或“这件事发生在<单点日期>。”；范围、假设、问题、引用、拒绝保存或其他事项不写入。此收窄入口不自动从任意聊天匹配知识缺口。

实际共享解析器用答复自己的时刻解释“昨天”等，原事件 `said_at` 保留。事实保存绝对 `event_at`、实际答复表达/时刻/消息ID，并追加答复原话引用；没有扩大敏感保存授权。缺口变为 resolved，原生L3不再继续追问；事实和原答复都在上下文修订依赖闭包内，旧快照立即失效。

回执 `ids=[变更proposal ID,知识缺口ID]`，`revision` 是新事实修订，`context_revision` 是内部变更记录修订。它们不是 Agent generation 或已通过提交门的对外更新证明。

`MemoryEventAnswerUndoService(memory, clock=...).undo(owner, subject, change_id, expected_revision=..., message_id=..., operation_id=...)`：需要明确原话“撤销这次事件日期确认”。逐字段恢复旧事实，重新打开同ID缺口，问题/状态/原来源恢复；事实审计修订、缺口审计修订和其目标版本绑定递增，准备时钟更新到重开时刻。为使后续隐私级联依然有效，缺口只在同一owner事务内短暂移除依赖，清派生后立即恢复；级联或重建失败则整体回滚，不留下失去依赖的缺口。任何来源撤销、后续修改或原授权失效均拒绝恢复，缓存回执同样复核。每条确认/撤销原话只授权一个操作。

补 `prepared_at`/`confirmed_at` 应用Clock记录，防止后接收但倒填日期的动作越过时间守卫；旧整理记录只回退到已有审计时刻，不补造历史时间。无迁移/正式编号；回滚用普通反向提交。
