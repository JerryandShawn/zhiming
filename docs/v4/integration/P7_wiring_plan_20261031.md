## 没做（和原因）

纯模块自己的回执写明，下面这些必须由持有租约、围栏和事务的主线路径接线，我没有硬接：

1. **背景车道和每分钟扫描**：到期的跟进由谁在什么事务里领取、怎么防重复。需要 `lane=background` 的运行、租约和 fencing，以及一张保存到期项的表。要新迁移（`CREATE TABLE IF NOT EXISTS`，带 `lock_timeout`），号码接在第二批之后；我没有用号，等裁定。
2. **PG 授权重核**：模块的输入是 source 投影，不是 PG 授权认证。准备和 Outbox 领取事务必须重新加载 owner、subject、原话授权、版本、撤销、活跃状态和日计数。
3. **消息落库与 Outbox**：晨报和跟进是否用现有 `report_schedules` 的发送链路，还是新增 Outbox，两种接法的幂等和"未知结果不重发"语义不同。
4. **ContextEngine 和提示词接线**：晨报的"生成输入包"到真实生成文字，要接模型、命理线的晨报内容、语气自查。
5. **HTTP 和飞书文字发送**：免打扰（22:00–08:00，08:30 补发）、每天最多 2 条（不含晨报）、晨报默认 07:00，这些规则在纯模块里，发送入口要主线接。
6. **验收**：脚本场景 Q/P/PR/T13、真实 PG 并发领取、真实 Outbox，都没跑。

## 建议顺序（给大脑和主线）

1. 先定第 1、3 两点的接法（要不要新表和新迁移号）。我的建议：新增一张 `core_proactive_queue` 表和一个 Outbox 表，按"领取事务重核授权、发送前写入 unknown、unknown 不重发"来做，只新增表，不改旧表。
2. 主线或模块线按这个接背景扫描和领取，纯模块不动。
3. 用假飞书服务和 `ScriptedProvider` 做 Q/P/PR/T13，再过完整 `tests/v4`。
4. `proactive` 到上线前一直是 false；开关打开要大脑放行。
