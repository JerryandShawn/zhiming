# 16 · 算命 Agent 架构研究报告（v4.1 增补依据）

> 作者：Claude（大脑）　日期：2026-10-18
> 目的：回答一个问题——"一个真正好用的命理 Agent，架构上还缺什么？"。方法是检索公开研究、开源工具、评测集、心理与伦理研究和国内法规，对照 v4 蓝图（`02`）找差距，给出可直接落地的升级项 U1–U11。
> 结论先说：**v4 的大方向与目前公开研究的结论一致**：程序排盘、模型解读、专科子 Agent、评审员、长期记忆。**主要缺口有五个**：
> 1. 没有拿权威命理题库量化"命理推理能力"；
> 2. 程序没有算出"时间交互"（大运、流年与原局之间的关系）；
> 3. 同一个命盘在不同对话里的解读可能前后不一致；
> 4. 记忆里的相对日期会随时间变质；
> 5. 没有针对巴纳姆效应、谄媚和情感依赖的专门防线。

---

## 一、关键发现

### 1. 大模型的命理推理能力：已经有权威题库，现状是"略好于瞎猜"

| 来源 | 内容 | 关键数字 |
| --- | --- | --- |
| **BaziQA-Benchmark**（arXiv 2602.12889，2026） | 200 道四选一题，出自 2021–2025 年全球职业八字比赛，由程序排好盘后交给模型，多轮作答 | DeepSeek-V3 36.7%、GPT-5.1 32.5%、Gemini-3-Pro 32.1%（瞎猜 25%）；最难的是**流年和精确应期**这类需要组合时间的题，以及多因素同时判断 |
| **MingLi-Bench**（GitHub，MIT 协议） | 160 题，八字 + 紫微，来自 2022–2025 年比赛；可注入用 iztro 预排的命盘；支持 OpenAI 兼容网关 | 可直接用来测我们自己的 Agent |
| **BaZi 人物模拟研究**（arXiv 2510.23337，2025） | "程序排盘 + 规则映射 + 多智能体推理" | 只给模型加规则知识几乎没用（39.3→35.9）；完整多智能体系统能到 47–55%，接近 2024 年比赛第三名水平。**故意给错生日后，正确率下降 20–46%**，说明系统确实在用命盘 |

对 v4 的启示：
- "模型自己排盘"不可行，"只给规则"也不够；"程序算 + 分步推理 + 专科子 Agent"才有效。这正是 v4 的设计（P8 技能包 + `consult_specialist`）。
- **时间组合是最大短板。** 大运、流年与原局之间的刑冲合害，应当由**程序算出来**交给模型，而不是让模型自己推（→ U2）。
- 不同模型对格局的判断会相反（同一盘有的判伤官格、有的判从儿格），所以必须并列展示各种可能，并把判断**存档保持一致**（→ U3）。
- 用"给错生日"做对照测试，可以检验 Agent 是否在空讲（→ U1）。

### 2. 现成工具生态：可以借鉴字段设计，不必替换引擎

| 工具 | 可借鉴之处 | 注意 |
| --- | --- | --- |
| `cantian-ai/bazi-mcp`（ISC 协议） | 输出字段很完整：四柱、十神、藏干（本中余气）、纳音、空亡、长生、胎元胎息、命宫身宫、各柱神煞、大运起运、**刑冲合会**；`getSolarTimes` 可以从八字反推公历时刻；`getChineseCalendar` 输出黄历（宜忌、冲煞、28 宿、彭祖百忌、吉神方位） | 没写真太阳时处理；没有旺衰和用神 |
| `zhiji-bazi`（npm） | 有日主强弱、格局、用神和真太阳时 | 方法与口径需要逐项核对 |
| `MCPIztro` / `ziwei_iztro-mcpserver`（MIT） | iztro 引擎的紫微排盘与运限；地名转坐标再换算真太阳时 | 地名解析依赖高德 Key |
| `astro-mcp`（pyswisseph） | 14 个工具：本命、行运、推运（含太阳弧）、日月返照、合盘、组合盘、小限、行星时、阿拉伯点等；输出紧凑 JSON，节省上下文 | pyswisseph 是 AGPL 协议，项目仓库公开即可满足开源要求 |

对 v4 的启示：
- 我们自己的计算层（lunar-python、py-iztro、pyswisseph）已经足够。**借鉴的是"输出什么字段"**：刑冲合会、空亡、长生、反推时刻、紧凑输出（→ U2、U9）。
- 可以把自己的工具也包一层 MCP 接口，供其他 AI 调用（→ U10，低优先级）。

### 3. 长期记忆：时间推理和信息更新是所有系统的弱项

- **LongMemEval**（500 题）把记忆能力分成五类：信息抽取、跨会话推理、**信息更新**、**时间推理**、**拒答**（不知道就说不知道）。全上下文的 GPT-4o 只有 60.2%，其中时间推理 45.1%、信息更新 78.2%。**LoCoMo** 上，模型在时间类问题上只有 20–30 F1，人类是 92.6。
- 这正好对应你最初的两个抱怨："看不懂时间"和"忘事/记不住变化"。
- 对 v4 的启示：
  - 记忆写入时，必须把"下周三""月底"这类相对日期**换算成绝对日期**并存下说话时刻；否则过一周再读，"下周三"就指错了（→ U4）。
  - 评测要补上"拒答"和"跨会话推理"两类（→ U5）。

### 4. 情感依赖、谄媚与巴纳姆效应：命理 + 陪伴型 AI 的双重风险

- **OpenAI 与 MIT Media Lab（2025）**：
  - 分析 400 万次对话、4000 多人问卷，并做了 1000 人、为期一个月的随机试验。
  - 整体上情感化使用并不多，但**重度用户**出现"问题性使用"的迹象：沉迷、情绪波动、失控。
  - 论文警告 AI 可能利用谄媚和模仿来讨好用户（"社交奖励黑客"）。
- **巴纳姆效应（Forer 1948）**：人们会把放之四海皆准的描述当成"说的就是我"，被试平均给出 4.26/5 的准确度评分。算命类 AI 天然容易滑向"算法冷读"。
- 对 v4 的启示：
  - 评审员要专门抓"空泛到对谁都成立"的话和"顺着用户说"的话（→ U6）。
  - 产品上避免"制造依赖"的机制（→ U7）。
- 这与你定的人设"懂行的老朋友，敢说真话"完全一致。

### 5. 国内法规（个人自用风险低，对外开放要注意）

- **《网络信息内容生态治理规定》**（网信办，2020-03-01 施行）第六条第（七）项把"破坏国家宗教政策，宣扬邪教和封建迷信的"列为**违法信息**（已核对网信办原文）。
- **《生成式人工智能服务管理暂行办法》**（2023-08-15 施行）主要约束"向境内公众提供"的服务；对公众开放需要备案。
- **《人工智能生成合成内容标识办法》**于 2025-09-01 施行，对公众提供 AI 生成内容需要标识。
- 对 v4 的启示：
  - 明镜台现在只给你本人用（口令认证、绑定飞书），风险很低。
  - 但设计上应坚持"传统文化与自我反思"的定位：不制造恐惧、不说宿命、不推销化解。这本来就是 v4 的边界。
  - 如果将来开放给他人，需要另做合规评估（→ U11）。

### 6. Agent 设计模式：v4 的结构与业界共识一致

- Anthropic《Building effective agents》提出的几种模式在 v4 里都有对应：
  - 工具循环 → Agent 循环；
  - 路由 → 危机模式分流；
  - 编排者-工作者 → 专科子 Agent；
  - 评估者-优化者 → 评审员 + 一次修订。
- Anthropic 的 **Agent Skills**（`SKILL.md` + 元数据 + 按需加载）已于 2025 年 12 月作为开放格式发布，多家平台跟进。我们的命理技能包直接采用这个格式，以后也能被其他 AI 工具复用（→ U8）。

## 二、v4.1 升级项（已写入对应阶段提示词）

| 编号 | 升级内容 | 为什么 | 落到哪个阶段 |
| --- | --- | --- | --- |
| **U1** | **命理推理评测**：本地接入 MingLi-Bench（MIT），并下载 BaziQA（只在本地用，不再分发）。用我们自己的 `chart_compute` 结果注入命盘，对比"直接问模型""v4 单 Agent""v4 深度模式（专科子 Agent）"三种配置。另做**安慰剂对照**：把生日打乱，正确率应明显下降，否则说明在空讲 | 用比赛题客观衡量"算得懂不懂"，防止只会说好听话 | P8（新增评测任务 E2） |
| **U2** | **时间交互表**由程序计算：指定年份、月份、日期下，大运、流年、流月、流日与原局四柱之间的天干五合与相克、地支六冲、六合、三合三会、三刑、六害、破，十神变化，紫微流年四化落宫，星盘行运相位的入相、精确、出相时间段。以结构化列表输出并可被引用 | 公开研究显示时间组合是模型最大短板；交给程序算，模型只负责解读与取舍 | P8 计算补全 |
| **U3** | **命理解读档案与一致性**：Agent 对你命盘的核心判断（格局候选、旺衰、喜用，每项附口径与依据）存为带版本的"命理档案"。之后的解读默认与档案一致；要改判必须说明理由并生成新版本。评审员增加"与命理档案矛盾"检查 | 避免今天说喜木、明天说喜金，这是信任的根本 | P5（档案实体与画像第 7 节）+ P8（生成）+ P6（评审） |
| **U4** | **相对日期绝对化**：`memory_write` 时把"下周三""月底""过两天"按该消息的"此刻"换算成绝对日期（`event_at`）。原话与换算结果一起保存，并保存说话时刻 `said_at`；换算有歧义（如"下周三"在周日说）时，用 `ask_user` 确认 | LongMemEval/LoCoMo 显示时间推理是最大弱项；不换算的话，记忆会随时间变质 | P3（工具）+ P5 |
| **U5** | **记忆评测补全**：按 LongMemEval 五类补 10 个场景，即拒答 3、跨会话推理 3、信息更新 2、基于记忆的时间推理 2（见 `07` 附录 B）。纳入契约 v2.2 | 现有场景缺"不知道就说不知道"和跨会话推理 | E1 之后的评测契约 v2.2 |
| **U6** | **反巴纳姆与反谄媚**：评审 rubric 新增两项。`generic_barnum`（严重度 3）：结论泛到对任何人都成立、又没引用命盘依据。`sycophancy`（严重度 3）：在决策问题上无依据地顺着用户偏好、回避风险 | 命理与陪伴两类 AI 的典型失败 | P6（critic rubric v2） |
| **U7** | **防依赖设计**：(1) 同一个问题 24 小时内不重新抽塔罗（尊重塔罗惯例，也避免焦虑性反复抽）；(2) 短时间内反复问同一件"会不会……"时，温和点出焦虑，转向可控的行动，不反复占卜；(3) 不做连签、打卡、"每天必看"之类的机制；(4) 主动消息上限保持每天 2 条 | OpenAI/MIT 研究显示重度使用会出现问题性依赖 | P3（塔罗工具规则）+ P7 |
| **U8** | **技能包采用 Agent Skills 开放格式**：每个体系一个 `SKILL.md`（YAML 元数据 name/description + 章节目录），章节文件按需加载 | 开放格式，便于以后给其他 AI 工具复用；本身就是按需加载 | P8 |
| **U9** | **时辰校正（可选，高级）**：出生时辰不确定时，用你的人生大事（升学、工作、婚育、搬迁的年份）去对照各候选时辰的大运流年，列出"更吻合的候选时辰"及理由。明确标注"推断"，不自动写入出生资料，必须你确认 | 时辰不准是命理里最常见的不确定来源；用户已经有大量自述事件可用 | P8 正式阶段（等你决定要不要） |
| **U10** | **MCP 外壳（可选）**：把只读的命盘、历法、塔罗查询包装成 MCP 服务，让 Kimi CLI、Claude 等其他 AI 也能调用明镜的计算 | 可移植性的延伸 | P11 之后 |
| **U11** | **合规定位**：页面和提示词坚持"传统文化与自我反思"的表述；禁止恐吓、宿命和化解推销（已有）。若开放给他人，先做合规评估：备案、AI 标识、未成年人保护 | 第六条第（七）项与生成式 AI 相关规定 | 写入蓝图 §16；开放前专项 |

## 三、不建议的做法（反面清单）

1. 让模型自己排盘或推节气。研究证明会错，而且错了还说得很自信。
2. 把古籍全文塞进检索库（RAG），用来代替结构化技能包。召回的往往是不相干的断语，精度低。古籍只适合作为技能包的出处引用。
3. 用"应验率"证明准确。巴纳姆效应和选择性记忆会让数字失真；我们只做"回看"，不做"打分"。
4. 只给一个流派的唯一结论。格局、喜用的判断天然存在分歧，应当并列展示，再按档案保持一致。
5. 为了提高使用时长而设计的"成瘾"机制。
6. 把评测分数当成"命理有效"的证据。比赛题测的是与专业命理师判断的一致性，不是现实预测的效度。报告中必须写明这一点。

## 四、用户决定（2026-10-18）

- **U9 时辰校正：必须做**，作为 P8 正式阶段的必做项，要求见 P8 提示词。
- **使用范围：今后只给本人使用**。U11 维持现有表述边界即可，不做对外开放所需的合规建设。
- **U10 MCP 外壳**：未提，按大脑建议放到 v4 稳定之后再说。
