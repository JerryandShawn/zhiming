# 明镜台 v4：模块候选使用补充

更新日期：2026-10-21，北京时间。供本人阅读；文中“小岚”和她的所有安排均为虚构示例。

本页补充 [09 号使用说明书](../09_产品使用说明书.md)。09 号描述的是改造完成后的体验；本页说明模块线已经在本机验证的规则，以及接入后应有的使用方式。

**本分支仍是候选：尚未接入主线实际运行入口，也没有完成真实网页、手机、飞书或定时投递验收。**
下文提到的确认、保存、撤销、订阅和卡片刷新流程，还需要主线与界面接入。看到本地测试通过，不能理解为这些入口已经出现在你的页面上。

## 1. 先看当前能证明什么

“本地已验证”指使用合成资料运行过规则检查；“待接入”指真实使用所需的后续工作。

| 能力 | 本地已验证 | 当前状态与限制 |
| --- | --- | --- |
| 相对日期与时刻 | 按原话发生时间换算；歧义保留候选 | 记忆保存、实际提醒与澄清界面待接入 |
| 生日、纪念日、英文日期 | 缺资料、闰日、闰月、周期与时区歧义时要求澄清 | 生日资料变更后的保存与提醒依赖尚待接入 |
| 记忆与敏感确认 | 原话溯源、拒记优先、确认范围、冲突与撤销规则 | 真实写入、成功回执、确认与撤销页面待接入 |
| “关于我” | 八个分节、原话依据、推测标记、来源失效过滤 | 页面读写与后台反思待接入；命理第七节保持未验证 |
| 整理与归区 | 标签候选、待整理、审阅、撤销冲突保护 | Q5 弃权比例超出门槛，**不得自动应用真实历史** |
| 旧对话整理试跑 | 合成导出转换为预览和撤销候选 | 真实导出格式、真人历史审阅、真实应用和撤销尚未验证 |
| 分区上下文 | 当前话题、其他区近况、全局约束的取舍 | 尚未接入真实对话上下文与区、话题界面 |
| 晨报、周报、月报、季报 | 内容分段、期间、当前来源与依据检查 | 订阅、实际定时器、报告历史页面与投递待接入 |
| 提醒与跟进 | 免打扰、迟到、每日上限与来源变化规则 | 真实任务领取、送达、手机锁屏表现尚未验证 |
| 飞书卡片 | 卡片内容、按钮过期规则与流式状态检查 | 真实权限、回调、发送、重启恢复和客户端体验尚未验证 |

## 2. 说日期时，把“哪一天”和“有没有提醒”分开

日期按照**说这句话的当时**解释，不按系统后来整理它的日期解释。默认使用北京时间；另有时区时需要明确说明。

例如，虚构的小岚在 2026-10-17（周六）说“下周三面试”，可得到 2026-10-21（周三）的日期候选。
同样一句话若是在 2026-10-20（周二）说的，“下周三”则是 2026-10-28。后台过了几周再整理，也应保留当时的含义。

接入后的记忆需要同时保留：

- 原话：“下周三面试”。
- 这句话是什么时候说的。
- 核对后的绝对日期，以及必要的时区。

绝对日期便于查找，原话便于你核对；不能把改写后的句子冒充当初逐字说过的话。

遇到以下情况，应先澄清：

- 周三当天只说“周三”，没有说明指今天还是下一次周三。
- 说“今晚凌晨两点”“过几天”“年前”“下学期”，还缺少明确口径。
- 写“04/05”，没有说明是 4 月 5 日还是 5 月 4 日。
- 一句话包含几个独立日期，不能只处理其中一个就说全部明确了。
- 在有夏令时的地区，某个当地时刻不存在，或同一个时刻出现两次。

生日和纪念日还要核对是谁的资料。没有已确认资料时不能猜；说“妈妈的生日”也不能套用本人的生日。
2 月 29 日遇到非闰年、农历闰月当年不存在时，要先确认怎么过。说“每年生日”属于循环意图，不能只算出下一次日期就当作一个普通单次事件。

工作日与假期要按已公布的放假、调休资料处理。节日的历法日期不等于放假安排；资料不足时应明说，不按普通周末猜“节后第一个工作日”。

“周三面试”可以形成安排候选。只有明确要求提醒，才可按“明确提醒”的时间例外处理；不能因为有日期就声称“已经设好提醒”。
当前生日解析也只是日期候选，尚不能据此承诺生日提醒已经排好。

## 3. 记忆：先看原话，再看确认和保存结果

本地规则支持“默认记住普通近况、计划、喜好和目标”，同时保留撤销能力。
**只有主线真正保存成功并返回回执，才可以显示“记下了”或“已保存”。**
解析出日期、形成提案、问过一次，都不等于保存成功。

健康、他人隐私、具体金额与债务、性取向、宗教政治立场、法律纠纷等内容，需要先确认。
自己的出生资料走专门的资料核对流程。口令、证件号码、银行卡号等秘密不进入普通记忆。

接入后的确认应让你明确选择“记住”“不用”或“以后这类都记”：

- 同一条原话的同一个确认问题，不反复催问；未同意时继续保持待确认。
- “以后这类都记”不覆盖你这次明确说的“不用”。
- 原话更正、资料版本变化或来源撤回后，不能拿旧同意继续处理新内容。
- 普通整理审阅也不能代替敏感记忆的确认。

“这个别记”“不要保存这段”和无痕优先。即使你以前允许记某类内容，这一次的拒绝也有效。
“别忘了记住”或“不用每次提醒我，记住这个目标”与拒绝保存不同，需要按完整句子理解。

小岚先说一个偏好，后来明确更正时，应区分“更新了什么”与“等待核对什么”。确定的同槽更新才形成更新候选；
拿不准的矛盾应保留两次原话，温和确认，不能悄悄覆盖。
现有局部规则并不理解所有语义更正，不应把没有识别出的矛盾说成已经处理好。

助手自己的建议和归纳会另标“推测”或“我上次的建议”，不能变成“你说过”。

## 4. “关于我”：能查依据，固定和手改也有边界

候选视图保留八个分节：称呼与基本情况、现在的生活、在意的事与目标、重要的人、偏好与禁忌、沟通偏好、命理档案摘要、正在跟进。

每个可显示条目都需要当前仍有效的事实和原话依据。缺少当前版本、原话被撤回或依据已经失效时，应先停止显示相关内容，再重新核对。
“固定”或“我手动改过”不能让已撤回来源重新出现；后台也不能悄悄覆盖你固定或手改的条目，只能给出建议。

条目有依据，不代表归纳一定准确。可以要求查看原话和日期，核对它有没有理解错。
推测应明确写成推测，原话里的链接、符号和排版只作文字显示。
命理第七节目前缺少权威档案接入，不能用开发示例或旧的“可信”标记补成真实盘面判断。

后台反思目前只验证了调度与候选规则：空闲十分钟、当地凌晨三点兜底，以及工作前重新核对来源。
没有真正入队、调用模型或保存新记忆。页面中的“我整理时补记了 N 条”仍待真实保存和回执接入，当前不能据此声称已经补记。

只有明确的结束时间或有效期，才形成到期归档候选。时间到了不代表事情实际结束；例如面试约在九点，不能据此断言面试已经完成。

## 5. 七个区之外，保留“待整理”

七个默认区是日常、事业学业、感情人际、家庭、身心、财务、命理研习。
“日常”是一个有含义的区；**没有把握的内容进入待整理，不能为了填满分类而塞进日常。**

同一话题继续聊时，候选会尽量保持归属；跨两个领域时可以建议主区和副区。
例如虚构安排“因家庭原因考虑换城市工作”，可能同时涉及事业与家庭，最后归属需要审阅。

当前整理质量仍有限：Q5 的弃权比例超出验收门槛。即使某些候选看起来明确，也只供人工审阅，不能自动整理你的真实历史。
未配置本地模型时不会自行下载；打开整理预览也不应自动调用 Kimi。可选的模型润色标题仍是待接入设计项。

接入后的安全流程是：先看整理建议，再调整归属或忽略，确认后才应用。
整理只增加区、话题等标签，不改写或删除原始对话；给事实、笔记、事项、塔罗记录或旧档案加标签，也不改变其原本内容。
助手回答可以随话题归类，仍保留助手身份，不能因此变成用户事实。

话题连续十四天没有新消息时可形成归档候选，保留原话与摘要；有了新消息，旧归档候选就需要重新核对。
已有事项不会因此被自动认定为完成。升级事项需要明确的目标原话，“如果以后……”或“我不想……”不能被自动当作已定目标。

## 6. 应用和撤销，都要看有没有后来变化

整理确认绑定的是当时那一份建议。原话、标签或话题后来变化时，旧确认不能继续套用。

例如虚构的小岚确认过一批“学习计划”标签，随后又手动把其中一条移到别的话题。
撤销旧批次时，不能抹掉这次后来的修改；相关字段或话题被新消息使用时，需要显示冲突并重新审阅。
“拿到一份撤销预览”不能显示成“全部撤销成功”。

归区撤销只处理相应标签，不等于删除原话，也不等于撤销另一条记忆。
来源已经撤回时，不能靠撤销、重放、去重或固定条目把它复活。重复提交同一次操作也不应重复产生效果。

旧 v3 历史工具目前只接收显式合成格式，生成试跑预览、待整理和冲突列表。
它没有读取你的真实历史，没有真实应用或删除入口；真实导出格式、逐批审阅和实际撤销还需要单独接入与授权。

## 7. 分区帮助接着聊，仍保留其他近况

本地投影规则会优先保留当前区的相关资料、当前话题最近三十轮完整对话，以及其他区最近七天的少量近况。
其他区的进行中话题保留标题；用户约束始终全局保留。当前区检索得到优先，不把其他区隔绝掉。

这些规则还没接入真实对话上下文。摘要只是依赖原话的派生内容，不能当新增用户事实；原话失效时，对应摘要也要失效。
分区本身不会授予访问其他人物资料的权限，也不会跳过无痕、拒记和敏感确认。

## 8. 报告里区分事实、安排和象征解释

候选晨报可编排今日历法、分区安排、到期跟进和可用的流日资料；周期报告可编排周报、月报和季报。
它们目前只生成内容，尚未创建真实订阅、定时任务、报告历史或通知。

阅读时需要分清：

| 内容 | 应如何理解 |
| --- | --- |
| 用户事实 | 有当前有效来源，保留原始事件时间或说话时间 |
| 安排 | 计划中的事情，结果未确认；不能写成已经完成 |
| 跟进线索 | 值得后续核对的事，报告本身不执行提醒 |
| 象征解释 | 有盘面依据与时间范围的文化解释，不是已发生经历或结果保证 |
| 合成示例 | 开发用的虚构材料，不是你的命盘，不作为专业依据 |

当前周期口径沿用旧版：周报以周一至周日为一周；月报和季报覆盖所选日期所在的月、季。
例如选择 2026-10-01 的月报，期间是 10 月 1–31 日，不自动改成回顾 9 月。
跨年周的标签年份可能与当天日历年份不同，期间仍应清楚列出。

有事件日期时按原事件时间归期，没有时按原话时间并注明“记录于”；不能用整理当天冒充当初发生时间。
缺少可用记录只表示资料不足，不等于这段时间什么都没发生。已归档或失效条目也不会为了凑报告被自动复活。

目前可用的 P8 证据是单日北京时间十二点的快照。只有 10 月 21 日的快照，就只说明这一天的该时点；
不能扩成全周、全月或全季趋势。不同日期的依据要分别保留，查过但未展示的依据也不能算成报告已经使用。

## 9. 通知开关、迟到和卡片按钮

以下是本地已验证、仍待真实投递接入的规则：

| 情况 | 规则 |
| --- | --- |
| 已订阅晨报 | 按订阅时刻，默认七点；可豁免普通免打扰，全局停用、静音与来源撤回仍优先 |
| 明确要求的提醒 | 到约定时刻可提醒，即使处于免打扰；必须仍有有效来源和当前权限 |
| 明确提醒迟到不超过一小时 | 可带“晚了几分钟”的说明；迟到年龄按原约定时间算 |
| 超过一小时且遇免打扰 | 顺延到免打扰结束，默认八点；自定义时段按设置保守处理 |
| 超过十二小时 | 只留网页收件箱，不再推送，也不能塞进晨报重新推一次 |
| 普通主动跟进 | 受每日上限、免打扰和接收情况限制；每日最多两条，不把晨报与明确提醒算入此额度 |

普通跟进默认在免打扰结束后八点半恢复；它与迟到的明确提醒不是同一类规则。
自定义免打扰结束时刻的最终口径仍待设计确认，不能为了固定八点而越过你设置的更长安静时段。
真实投递、暂停与恢复效果都尚未验收。

**D4 的决定继续有效：不开使用时长提醒，不登记紧急联系人。**
这批候选不增加打卡、连签或催你回来的消息。锁屏预览应隐藏敏感正文；本机规则检查不代表手机真机表现已经验证。

接入后的卡片按钮也需要当前身份、来源和有效期：普通提问、选择、记忆回执及晨报按钮按二十四小时；
删除记忆、删除原话、应用整理等高风险确认按十五分钟。不能因按钮放在普通提问卡上就延长危险动作的有效期。

只有正确绑定且确实过期的按钮，才对应“这张卡已过期，我重新发一张”的候选提示。
当前模块只产生刷新意图，没有真的补发卡片，也没有执行原动作；身份不符、按钮已撤销或内容已变化时，应要求重新核对。
重复点击应识别为同一次操作，不能重复保存或删除。

卡片显示中断或发送结果不明时，系统应先核对状态，不能靠换卡或重复发送绕过去重。
本地流式规则也不代表手机上已经逐字显示、按钮已经可用或消息已经送达。
