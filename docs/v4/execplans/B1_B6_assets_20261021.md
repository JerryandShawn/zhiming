## Surprises & Discoveries

systemd 的 IPAddressDeny/Allow 依赖主机 eBPF 支持，配置文本存在不证明生效。未来验证必须以本机已核私有 IPv4 的一次性高端口 listener 为阳性对照，再由同新 unit 的 ExecStartPre 尝试被禁止的连接；不访问公网或供应商。没有可用私有 IPv4 或内核能力则阻塞，不用外网连接失败冒充隔离成功。为了避免 IPv6 未验证旁路，本模板仅允许 AF_UNIX/AF_INET，并在预检实测 IPv6 socket 创建被拒。

环境文件不能放真实模型 key 或真实网页登录 token。新合成 token 在服务器受保护新目录生成，只存文件、只注入当前 Web 进程；env 只写该文件与 PGPASSFILE 路径。包装器明确拒绝继承真实 token/provider key，登录检查也不把 token 放 argv/stdout。

固定 b9 的 ConfiguredModel.__init__ 只读配置，缺key不会阻止from_base构造；generate才在任何HTTP前拒绝。checkpoint表若缺失仍会使from_base失败，因此先由owner执行固定PostgresSaver.setup、writer预检max migration，再允许Web启动。不能用合成假key或真实chat探针“解决”启动问题。

纯静态检查首次发现一个未使用import，已删除；含中文片段经Windows默认编码送Ruff产生解码错误，改为原始UTF8字节复验，9段均通过。这个修正属于校验传输，不是调整业务断言。SQL与INI结构检查不等同PG/systemd原生解释。
