# P8 · 命理能力重建与旧分析重算

> 前置：P3 已合并。可与 P5–P7 并行。这是"算命助手"的专业核心，质量要求最高。

---

你是「知命明镜台 v4」的开发者（Codex）。先读 `AGENTS.md`，再读 `docs/v4/02_v4架构蓝图.md` §12、§11（`chart_compute`、`chart_skill`、`consult_specialist`）、§16，`docs/v4/06_明镜台系统提示词.md` 的 P1"命理与塔罗"段与 P7 specialist，以及仓库内的 `mingjing_core/adapters/charts/README.md`、`mingjing_core/knowledge/README.md`。按 `.agent/PLANS.md` 写 `docs/v4/execplans/P8_metaphysics.md`，分支 `v4/p8-metaphysics`。

## 背景

- v3 的知识包只有 16 条规则（八字 6、紫微 5、西占 3、塔罗 2），超出范围一律 `RULE_GAP`；模型基本在复述模板句。v3 明确未实现：旺衰、格局、调候、喜用神、独立四化飞宫、多流派格局、精确应期、完整古典尊贵/接纳、多种推运技术（`docs/AI_HANDOFF.md` §9）。
- **用户已确认的尺度：像真正的命理师，有依据地讲。** 可以谈喜用神、流年重点、吉凶趋势，但：盘面数据只能来自程序计算；每个判断注明依据（盘面字段）与流派/口径；有分歧并列；不预测死亡/重病/灾祸日期；健康、法律、投资不做保证；不恐吓、不推销化解。
- 用户还指出：**旧系统的分析不正确**（旧时间线月运、应验率、关系图、个人征兆词典里的分析结论），需要用新能力重新分析；命理技术能力也要重建。
- 现有计算：排盘在隔离 Python 环境中以子进程运行（`mingjing_core/adapters/charts/adapter.py`、`worker.py`），八字用 lunar-python、紫微用 py-iztro、西占用 pyswisseph（Moshier、热带黄道、Placidus）；`CalculationProfile/Artifact/Feature/TimeBranch` 契约记录口径与时间分支（`domain/calculation.py`）。旧 `hermes/bazi.py`、`ziwei.py`、`astro.py` 中有可复用的纯计算。

## 目标

1. **计算补全**（§12.3）：每个新增项都输出可复核字段、口径说明、引擎版本，进入 `CalculationArtifact`，可被 `〔c#〕` 引用。
2. **技能包**（§12.2）：八字、紫微、西占、塔罗四套分章知识文档 + 元数据，`chart_skill(system, topic)` 按需加载。
3. 知识注册表降级为**证据与常识校验**：检测与计算数据矛盾的说法（供评审员与结构检查使用），不再是"唯一允许的解释"。
4. `consult_specialist` 子 Agent（深度模式）。
5. **旧分析重算**：从原始用户原话与事件重新生成人物关系、事件情景、个人符号词典；旧结论标记作废。

## 设计要求

### A. 计算补全（charts 隔离环境内实现，经 `ChartAdapter` 暴露）
| 体系 | 新增 | 输出要求 |
| --- | --- | --- |
| 八字 | 藏干（本气/中气/余气）与月令司令；十神全表；旺衰评分（至少两种口径并存，例如"月令+通根+透干打分法"与"得令/得地/得势三项法"，分别给分与结论，不合并成一个"真理"）；格局候选（正格八格 + 从格判断条件是否满足，列出满足/不满足的条件）；调候用神表（按日主与月令查表，表格数据写入 `knowledge/` 并注明出处）；喜用候选（分别按扶抑、调候、格局三种思路给出，并标注一致/分歧）；起运岁数与大运全表（10 步）；流年、流月（指定年份）；常用神煞 ≤ 10 个（天乙贵人、文昌、驿马、桃花、华盖、羊刃、禄神、空亡等，标注"神煞属辅助参考"） | 每项 JSON Pointer 可引用；口径字段 `method`、`school` |
| 紫微 | 生年四化、宫干飞化（含自化、化忌冲）、三方四正、大限/流年/流月命宫与四化（py-iztro horoscope 能力优先，缺失的自行按口径实现并测试） | 记录引擎版本与口径 |
| 西占 | 行运对本命相位的**区间**（入相位、精确、出相位时间，给定期间内）；次限推运（日返一年法）；太阳回归盘 | 高纬 Placidus 失败显式报错（保持 v3 行为），不静默换宫制 |
| 日课 | 任意日期的流日/流月四柱、与本命日主的十神关系、与命局的冲合 | 晨报与"那天适合吗"使用 |

- 每一项都要有**单元测试**：用公开可验证的样例盘（例如知名人物公开生辰或教材例盘，写明来源），与至少一个独立来源（排盘软件或教材）的结果对照；对照来源与结果写进 `docs/v4/evidence/P8/calc-crosscheck.md`。
- 出生时间为区间/未知时，沿用 v3 的分支采样机制（`TimeBranch`），新增项也要说明在区间内是否稳定。

### B. 技能包（`mingjing_core/skills/<system>/`）
- 每个体系：`SKILL.md`（元数据：名称、章节列表、每章适用的问题类型与需要的盘面字段）+ 若干章节 Markdown（八字章节见蓝图 §12.2 示例；紫微：命身宫与主星、十四主星性质、四化与飞星、宫位组合、大限流年、常见误读；西占：行星/星座/宫位、相位、行运与推运、回归盘、常见误读；塔罗：大阿卡纳、小阿卡纳四元素与数字、宫廷牌、牌阵与位置、牌间关系、逆位的几种读法、常见误读）。
- 每章结构：方法步骤 → 需要哪些盘面字段（字段名与计算产物路径对应）→ 各流派观点与分歧 → 适用前提 → 反例与常见误读 → 表达示例（老朋友口吻、白话、带依据别名的示范句）。
- **来源要求**：每章末尾列参考来源（书名、章节/卷次）。古籍（如《渊海子平》《三命通会》《滴天髓》《子平真诠》《穷通宝鉴》《紫微斗数全书》）可以引用原文短句；现代著作只能用自己的话概括方法，不得大段摘抄（版权）。不确定的说法写"存疑"，不要编造出处。
- `chart_skill(system, topic)` 返回对应章节文本（单次 ≤ 6k tokens），在上下文中以 `<技能 system=… topic=… version=…>` 块出现。
- 用户会抽查技能包：在证据目录放一份 `docs/v4/evidence/P8/skills-review.md`，列出每章摘要与来源，方便审阅。

### C. 知识注册表降级
- `knowledge/registry.py` 的 `claims_for / revalidate_claims`（`:599, :701`）保留为"从计算数据生成可引用声明"的工具；新增 `contradictions(text_claims, artifacts) -> list[Finding]`：识别与计算数据直接矛盾的说法（例如说"甲木日主"但计算是庚金），供 P6 评审员输入与结构检查使用。
- 不再因为 `RULE_GAP` 阻止模型解释；`RULE_GAP` 改为告诉模型"该项没有程序计算支持，只能作一般性说明并标注"。

### D. `consult_specialist`
- 深度模式（用户说"详细看看/深入分析"或 owner 设置 `depth=deep`）可见；为指定体系创建子运行（`kind=subagent`），提示词 `prompts/specialist.md`（06 P7），独立上下文：问题 + 该体系的计算产物（带别名）+ 可用 `chart_skill`；返回要点与详细推理，主 Agent 综合。
- 子运行的步骤日志、取消、上限同主运行。

### E. 旧分析重算（`tools/reanalyze_legacy.py`）
- 输入：P5 标记了 `legacy_analysis_pending_reanalysis` 的旧时间线/关系图/词典/应验率实体，以及原始用户原话与事件。
- 输出（全部经过 P5 的写入策略与回执，后台通道运行）：
  - 人物关系 → 画像"重要的人"条目（只基于用户原话；无原话支撑的旧关系丢弃）；
  - 历史事件 → 情景记忆（带日期，过去时）；
  - 旧"征兆词典" → "你的个人符号词典"（只记录用户自述的联想，如"梦见水=你说会想到考试"，不作预言），作为笔记；
  - 旧月运/应验率 → **不导入**，仅保留原始数据归档（只读）。
- `--dry-run` 报告（数量与类别，不含正文）→ 用户确认 → `--apply`。

## v4.1 增补（来自 `docs/v4/16_算命Agent架构研究.md`）

- **U1 命理推理评测（任务 E2）**：
  - 本地接入 MingLi-Bench（MIT），并下载 BaziQA（只在本地使用，不再分发）。
  - 用我们自己的 `chart_compute` 结果注入命盘，对比三种配置："直接问模型""v4 单 Agent""v4 深度模式（专科子 Agent）"。
  - 另做**安慰剂对照**：打乱出生资料后正确率应明显下降。
  - 报告必须注明：这里测的是与职业命理师判断的一致性，不是现实预测的效度。
  - 真实调用遵守会员额度规则。
- **U2 时间交互表**：程序计算指定年、月、日下，大运、流年、流月、流日与原局四柱之间的以下关系，结构化输出并可被 `〔c#〕` 引用：
  - 天干：五合、相克；
  - 地支：六冲、六合、三合、三会、三刑、六害、破；
  - 十神变化；
  - 紫微流年四化落宫；
  - 星盘行运相位的入相、精确、出相时间段。
- **U3 命理档案**：生成并保存带版本的核心判断（格局候选、旺衰、喜用，各附口径与依据）。之后的解读默认与档案一致，改判时生成新版本并写明理由。
- **U8 技能包格式**：采用 Agent Skills 开放格式，即 `SKILL.md`（YAML frontmatter：name、description）加按需加载的章节文件。
- **U9 时辰校正（用户决定：必做）**：
  - **输入**：
    - 用户的出生日期；
    - 时辰的不确定范围（未知时取全天 12 个时辰，"大概"时取中心 ±N 分钟）；
    - 用户自述的人生大事，从记忆中自动收集并请用户确认。每件事要有年份（最好有月份）和类型，类型包括：升学/毕业、入职/离职、结婚/分手、生子、搬迁、亲人重大变故、重大疾病或手术、重大财务事件。
  - **计算**（程序完成，不交给模型）：对每个候选时辰（未知时按 12 个时辰，必要时细到交界前后各一个采样点），计算以下内容并输出结构化对照表：
    - 时柱、大运起运岁数与排序；
    - 每件大事发生那年的大运、流年与原局的交互（复用 U2 的时间交互表）；
    - 紫微命宫/身宫和当年流年四化落宫。
  - **评分**：采用透明、可解释的"吻合度"规则，规则写在技能包里，并标明是项目口径；对每个候选时辰，列出支持与不支持的证据条目。模型只负责解释，并挑出最值得追问的一两件事帮助缩小范围（用 `ask_user`）。
  - **输出与写入**：
    - 列出前三名候选时辰及理由，标注"推断，不是确认"；
    - 用户确认之前不改动出生资料；确认后走资料确认流程，并把时间精度标为 `rectified`（新增枚举值），同时保存依据；
    - 时辰校正的结论进入命理档案（U3），后续解读要说明"时辰为校正推断"。
  - **评测**：用合成人物做测试。先以已知时辰生成"人生大事"，再看校正能否把正确时辰排进前三。至少 10 个合成人物，前三命中率写进报告。必须同时报告随机基线（12 个时辰取 3 个，即 25%），不得夸大。
  - **界面**：命盘页的"出生资料"区新增"不确定时辰？帮我校正"入口；手机和飞书都要能完成整个流程（飞书用卡片按钮确认大事）。

## 测试与评测

- 计算：新增项单元测试 + 交叉核对文档。
- 评测：C01–C07、TA01–TA03 脚本模式通过；实测：C 类 ≥ 85%，评审 rubric 的 `unsupported_chart`、`fatalism`、`unsafe_advice` 零严重问题。
- 新增 10 个命理质量场景到 `tools/eval/scenarios/`（例如"我适合什么行业""今年感情怎么样""大运什么时候换""我和他合不合"（用户提供对方资料时的提醒与处理）），实测用评审模型 + 一个"命理质量 rubric"（依据是否标注、流派是否说明、是否落到现实、是否白话）打分。

## 验收标准

1. 计算补全全部有测试与交叉核对记录。
2. 四套技能包完成，来源清单齐全，审阅文档入库。
3. 评测达标，报告入库。
4. `reanalyze_legacy.py` 在合成数据上 dry-run/apply 正确；stage dry-run 需用户授权。
5. ExecPlan 与阶段回执。

## 何时停下来问用户

- 流派取舍有重大分歧、需要用户偏好时（例如他更信哪一派），给出选项；
- 交叉核对发现现有 v3 计算结果与独立来源不一致时（**立即报告**，不要自行"修正"现有口径）。
