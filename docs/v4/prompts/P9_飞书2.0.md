# P9 · 飞书 2.0：手机主入口（卡片、按钮、流式、免登网页）

> 前置：P3 已合并即可开始卡片与回调；流式卡片需要 P4；记忆回执卡需要 P5；跟进卡需要 P7。
> **用户在手机上主要用飞书**（手机浏览器不方便），所以这一阶段决定手机端体验。

---

你是「知命明镜台 v4」的开发者（Codex）。先读 `AGENTS.md`，再读 `docs/v4/02_v4架构蓝图.md` §4、§9、§13、§16，`docs/v4/08_设计规范_新中式.md` §9（飞书卡片模板），以及仓库内 `docs/CORE_FEISHU_GATEWAY.md`。按 `.agent/PLANS.md` 写 `docs/v4/execplans/P9_feishu.md`，分支 `v4/p9-feishu`。

## 背景

- 现在的飞书网关（`mingjing_core/adapters/feishu_gateway.py`）只接受 `sender_type=user`、`chat_type=p2p`、`message_type=text`；作者 open_id 必须匹配 PG 中的 `feishu/user` 绑定（`:66-68`）；P3 已改为"入站写库+入队，不执行咨询"。
- 出站：`mingjing_core/adapters/channels/feishu.py:10-26 FeishuTransport` + `channels/delivery.py:28-67 CoreDeliveryWorker`，经 Outbox（`adapters/delivery.py`）原样投递，送达不明不重发。
- SDK：`lark-oapi 1.7.3`（`build_sdk_client`，`feishu_gateway.py:159-166`）。注意：调研发现 `lark_oapi.channel` 模块已进入兼容维护期，新功能在 `lark-channel-sdk` 中发布——请核实当前官方推荐方式，在 Decision Log 记录选择。

## 目标

1. 入站支持图片与富文本（post）消息。
2. 交互卡片（JSON 2.0）：回答卡、提问卡（`ask_user` 选项按钮）、记忆回执卡（撤销）、提案卡（记住/不用/以后这类都记）、塔罗卡（点选牌背、揭牌）、跟进卡（快捷回复）、晨报卡、资料确认卡（打开网页确认）。
3. 按钮回调：`card.action.trigger` 经长连接；一次性 action token。
4. **流式卡片**：回答在飞书里逐字出现。
5. **网页应用免登**：在飞书里点"打开明镜台"直接进入完整网页（命盘、塔罗、关于我），无需输入口令。

## 设计要求

### A. 入站
- 图片：下载消息资源（需权限 `im:resource`），复用 `adapters/web.py:394-415 save_images` 的类型/大小校验与存储（`ZHIMING_MEDIA_PATH`），作为本轮图片附件；图片永远是"未验证附件"。
- post 富文本：提取纯文本与图片。
- 合并窗口（P3 已实现 2.5 秒）保持。
- 群聊、机器人消息仍不进入 Core。

### B. 卡片（`mingjing_core/adapters/channels/cards.py`）
- 模板严格按 `08_设计规范_新中式.md` §9（颜色、标题样式、按钮文案、长度限制）；卡片内容只来自信封与回执，不二次让模型自由生成。
- 每个按钮的 value 只放 `{"t": "<action_token>"}`；token 存 `core_action_tokens`（hash、owner、kind、entity_id、payload 指纹、`expires_at`、`used_at`），校验：绑定的 open_id 一致、未过期、未使用；使用后标记。
- 提问卡：选项按钮点击 → 等价于用户发送该选项文本（写入线程为用户消息，`channel=feishu_card`）并入队；附"我自己说"提示（直接打字回复即可）。
- 撤销按钮 → 调用 P5 的撤销服务；卡片更新为"已撤销"。
- 塔罗卡：展示牌背（P10 的 SVG 资源需转 PNG 上传为飞书图片，缓存 image_key），点选 → `select`；揭牌 → `reveal`（复用 `TarotService`，所有固定牌不变量保留）。
- 回调处理耗时超过 2 秒的操作：先返回空响应 `{}`，再异步更新卡片。

### C. 流式卡片
- 流程（实现前**必须对照飞书开放平台官方文档**核实接口路径、字段与限频；以下为调研所得流程）：创建卡片实体（`streaming_mode=true`）→ 以 `card_id` 发送消息 → 按严格递增 `sequence` 更新正文文本元素（节流 300–500ms，单卡 < 10 QPS）→ 结束时关闭 `streaming_mode` 并写入最终布局（含"命理依据"折叠区、回执、按钮）。
- 订阅 P4 的运行事件（同进程 hub 或 `LISTEN mj_run`）驱动更新；`text_reset` → 覆盖正文；`memory_receipt` → 在卡片底部追加回执行；`ask_user` → 最终布局为提问卡。
- 幂等与恢复：Outbox 记录 `card_id` 与最后 `sequence`（`reconciliation` 字段）；进程崩溃后，恢复程序把最终内容写入**同一张卡**并关闭流式；关闭失败 → 补发一条纯文本最终回答并在卡片上标"已完成，见下条"。送达不明仍遵守不重发原则。
- 免打扰时段与锁屏预览规则（P7）对主动消息生效；用户主动发起的对话不受免打扰限制。

### D. 网页应用免登
- 飞书开放平台需要用户（管理员）开通"网页应用"能力、配置可信域名 `p.jerrymeng.asia` 与重定向地址，并发布版本——**这需要用户在飞书后台操作，提前告诉用户需要开通的权限清单**（见下方"用户待办"）。
- 前端在飞书容器内（UA 检测）才加载飞书 JS-SDK（唯一允许的外部脚本，CSP 只对该页面放行对应域名），调用 `tt.requestAccess` 获取 code → `POST /api/auth/feishu {code}` → 后端用 app 凭证换 `user_access_token` → 取 open_id → 匹配 `core_channels` 绑定 → 签发 HttpOnly、Secure、SameSite=Lax 会话 cookie（`core_web_sessions`，30 天，可在设置页吊销）。
- 后端鉴权：保留 `X-Token`（`web.py:57-65`），新增 cookie 会话；两者任一有效即可；cookie 会话的写操作需校验 `Origin`/CSRF token。
- 卡片与晨报中的"打开明镜台"按钮使用飞书的网页应用打开方式（applink），深链到 `#/chart`、`#/tarot?draw=…`、`#/me` 等。

## 测试

- 单元：卡片 JSON 生成快照测试（每种卡片）；action token 生命周期；合并窗口；图片校验。
- 集成：用飞书传输替身（记录请求）跑完整流程：入站文字/图片 → 运行 → 流式卡片更新序列（sequence 单调、节流符合）→ 关闭；按钮回调（提问、撤销、塔罗点选）；崩溃恢复写同一张卡。
- 真实验证（stage，需授权）：一次完整对话、一次提问卡、一次撤销、一次塔罗、一次免登打开网页；截图存证（打码个人信息）。

## 验收标准

1. 图片消息能得到回答；按钮一次性且绑定身份；撤销可在卡片上完成。
2. 流式卡片每秒至少更新 2 次并最终落定；崩溃恢复写入同一张卡。
3. 飞书内打开网页免登成功，深链正确。
4. 全部测试通过；stage 真实验证截图（授权后）。
5. 管理员待办清单交付给用户。
6. ExecPlan 与阶段回执。
