你是「知命明镜台 v4」的开发者（Codex）。先读 `AGENTS.md`，再**完整**读 `docs/v4/02_v4架构蓝图.md` §6（全部）、§5.3、§16，以及 `docs/v4/06_明镜台系统提示词.md` 的 P1"记忆"段与 P3 reflection。按 `.agent/PLANS.md` 写 `docs/v4/execplans/P5_memory.md`，分支 `v4/p5-memory`。

## 背景（证据）

用户最大的抱怨是"它忘事"。根因（详见 `docs/v4/01_架构诊断报告.md` §2.2）：
- 写入闸门 `application/memory.py:199-200` 把除偏好/约束外的**所有**事实（背景、目标、事件、担忧）当作敏感 → `pending_confirmation`；前端只认 `saved`（`static/app.js:288`），pending 被静默丢弃，且没有确认接口。
- 迁移时旧的背景/目标/事件记忆被存为 `legacy_unverified + pending`（`migration_core.py:228-245`），被 `facts()` 排除（`memory.py:331`），而 `correct_fact` 要求 `granted`（`memory.py:241`）→ 永远无法恢复。这就是"以前记得、现在不记得"。
- 没有情景记忆（`Episode` 契约 `domain/contracts.py:80-89` 从未生成）、没有画像、没有向量检索。

**用户已确认的策略：默认记住 + 可见可撤销；敏感信息（健康、他人隐私、具体金额等）先问一次；用户说"别记"永远优先。**

## 目标

1. 新的写入策略与敏感分类（§6.2），回执实时可见、可一键撤销；proposal 可确认/忽略/"以后这类都记"。
2. 条目化用户画像"明镜台眼中的你"（§6.4），进入上下文 L2。
3. 后台沉思任务（§6.5）：情景、补记、合并去重、矛盾→知识缺口、画像更新、线程摘要。
4. 混合检索：PG 全文 + 本地向量（§5.3）。
5. 遗忘传播覆盖全部新派生层（§6.3）。
6. 旧记忆复活工具（§6.6），先 dry-run 报告，所有者确认后执行。

## 设计要求

### A. 策略（`mingjing_core/memory/policy.py`）
- `classify(quote, kind, model_hint) -> Sensitivity`：规则（关键词+句式，按 §6.2 表格的类别）与模型自报 `sensitivity` 取**较严者**。
- `decide(owner_settings, sensitivity, optout, secret) -> {save|proposal|stop|reject}`；owner 设置新增 `auto_save_categories: []`（"以后这类都记"写入这里）。
- 正例/反例测试：每个敏感类别 ≥ 10 条中文样例；OPTOUT 正反例沿用 P2 并扩充到 ≥ 20 条。
- `memory_write` 工具与 v3 的 `save_fact` 共用此策略（v3 运行仍使用 v3 的旧敏感规则，除非 owner `runtime=v4`——避免现网 v3 行为突变；写进 Decision Log）。

### B. 回执、撤销、确认（API）
- `POST /api/memories/{id}/undo {undo_token, request_id}`：校验 token（一次性、绑定 owner，存 `core_action_tokens`；该表由**本阶段新增的迁移 `0008_memory_proactive.sql`** 创建，0008 一次性包含蓝图 §15 所列全部内容：due 表达式索引、`core_action_tokens`、`core_web_sessions`，供 P7、P9 直接使用），调用 `retire_fact`（`memory.py:298-325`），走 `mutation()` 幂等（`web.py:91-100`）。
- `GET /api/proposals`、`POST /api/proposals/{id}/confirm {request_id, remember_category?: bool}`、`POST /api/proposals/{id}/dismiss {request_id}`：确认时调用 `grant_authorization`（`memory.py:118-123`）后写入事实。
- 回执通过 P4 的 `memory_receipt` 事件推送；同时写入助手消息的信封 `receipts[]`，历史中可回看。

### C. 画像（`mingjing_core/memory/profile_doc.py`）
- 实体 `profile_doc`：每条 `{id, section, text, source_ids[], fact_ids[], confidence, updated_at, pinned, edited_by_user}`；8 个分节见 §6.4。
- 后台工具 `profile_doc_patch`：无 `source_ids` 的新增条目拒绝；用户手动编辑的条目（`edited_by_user`）沉思任务不得覆盖，只能建议。
- API：`GET /api/profile-doc`、`PATCH /api/profile-doc/items/{id} {text, expected_revision, request_id}`（编辑会生成一条来源为"用户编辑"的消息+事实）、`DELETE /api/profile-doc/items/{id}`。
- ContextEngine L2 改用画像（P3 的临时实现删除）。

### C2. 命理档案与日期（来自 `docs/v4/16_算命Agent架构研究.md` U3、U4）
- 新实体 `chart_interpretation`：带版本，包含格局候选、旺衰、喜用（各附口径、依据别名、生成时间、改判理由）；它的摘要进入画像第 7 节。用户可以在"关于我"页查看历史版本。
- 记忆里的事件一律以绝对日期 `event_at` 存储，并保留原始说法与 `said_at`（工具侧换算见 P3 的 U4）。沉思任务要检查并修复缺少绝对日期的旧事件，有歧义的生成知识缺口来确认。

### D. 沉思任务（`mingjing_core/agent/reflection.py`）
- `kind=reflection`、`lane=background`；触发：线程空闲 10 分钟（调度器维护每线程的最后活动时间）+ 每晚 03:00 兜底；同一线程同一时间只有一个沉思运行。
- 提示词 `prompts/reflection.md`（逐字来自 06 P3）；可见工具：`memory_search`、`memory_write`、`memory_update`、`note_write`、`episode_write`、`gap_write`、`gap_update`、`profile_doc_patch`、`thread_summary_write`、`schedule_followup`（蓝图 §11 后台工具表）。
- 产出的事实回执汇总为一条系统便签，在用户下次打开对话时显示"我整理时补记了 N 条 [查看]"（不主动推送）。
- 无痕线程、被撤销的来源不处理。

### E. 检索（`mingjing_core/memory/retrieval.py`）
- 向量：本地 ONNX `bge-small-zh-v1.5`（模型文件路径由 `ZHIMING_EMBEDDING_MODEL` 指定，参考 `hermes/semantic_index.py:13-39` 的 Encoder 实现方式；模型文件不入库，写安装说明）；写入实体时异步生成向量（后台通道），存 `core_embeddings`；单用户规模用 numpy 余弦。
- 融合打分：`0.6·向量 + 0.4·全文`，时间衰减（半衰期 180 天，约束/目标类不衰减），同来源去重；返回带别名、日期、来源渠道。
- 模型文件不可用时自动退化为纯全文检索并记录一次警告（不报错）。

### F. 遗忘传播
- 扩展 `invalidate_derived`（`postgres.py:282-332`）：事实撤销/来源删除/`memory_forget` → 删除或重算：画像条目（按 `source_ids` 确定性删除）、笔记、情景（含该来源的情景重写或删除）、线程摘要（标记失效，下次沉思重算）、向量（数据库触发器已在 P2 建立，本阶段补测试）、运行事件与步骤正文、引用了该事实的助手消息（替换为"〔已删除的内容〕"并升 revision）。
- 评测 F01–F04 全部用确定性断言验证。

### G. 旧记忆复活（`tools/revive_legacy.py`）
- 严格按 §6.6 的 (a)–(e)；`--dry-run` 输出：各类数量、按类别统计、样例 ID（不含正文）；`--apply` 需要 `--confirm-token <dry-run 报告中的哈希>`，防止误执行；幂等；每次 apply 生成 `batch_id`，并支持 `--revert <batch_id>` 把该批次复活的记录恢复到复活前状态（P11 上线回滚要用）。
- (e) 旧时间线/关系图/词典/应验率的分析结论：给对应 legacy 实体打 `legacy_analysis_pending_reanalysis=true` 标记，不导入为事实（P8 重算）。
- 遵守撤销账本（`is_revoked` 与来源区间撤销）。
- 在 stage 上先跑 dry-run，报告交给用户与大脑确认后才可 `--apply`。
