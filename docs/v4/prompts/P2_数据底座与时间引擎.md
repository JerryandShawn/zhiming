## 背景（证据）

- **时间**：`application/consultation.py:26,42-43` 只有 `today()` 返回 `YYYY-MM-DD`，只放进 intake 的 payload（`:341`）；synthesis（`:504-514`）看不到今天；没有星期、时刻、农历、节气、节假日、调休；历史消息的 `at` 被丢掉（`:344,:510`）；报告不传 `selection.date`（`adapters/channels/reports.py:62-71`）。
- **看不到自己的话**：答案只存在 `core_runs.result`（`consultation.py:1002-1030`），历史只取用户 `message`（`application/memory.py:382-384`）。
- **会话隔离**：`conversation_id` 按 session/渠道切分（`web.py:426`、`feishu_gateway.py:70`、`memory.py:57,383`）。
- **记忆正则误伤**：`memory.py:11`（OPTOUT 把"别忘了记住"当拒绝）、`:191-192`（假设句窗口过大）、`:196`（第三人称误触）、`:12,:125-133`（授权词必须在事实之前）。
- **查询问题**：`repositories/postgres.py:174` 按 `created_at` 升序 `LIMIT 10000`（超过一万条取不到最新）；`memory.py:101-116,95` 对每条消息逐条查撤销（O(消息×撤销)）。
- **现成轮子**：`lunar-python 1.4.8`（目前只在 charts 环境，`requirements-charts.lock`），其 `lunar_python.util.HolidayUtil` 已内置 2026 年法定假日与调休（已核对与国务院 2025-11-04 通知一致），`Solar/Lunar` 提供农历、节气、干支、黄历宜忌。旧 `hermes/bazi.py:213 cmd_day` 有日干支与节气区间的写法可参考。

## 目标

1. **时间引擎 `timekit`**：任意时刻 → 公历、星期、时段、农历、节气（当前与下一个及交节时刻）、年月日时干支、黄历（宜忌/冲煞/建除/星宿）、法定假日/调休/周末/工作日状态、下一个假日与倒计时、未公布年份如实标注。
2. **"此刻"块**：严格按蓝图 §5.2 的样例格式生成。
3. **数据底座**：迁移 0005–0007、新实体种类、线程字段与回填、全文检索、查询修复、schema 校验放宽。
4. **v3 速赢**（现网可上线）：v3 模型 payload 里带上"此刻"块、带时间戳与渠道的**双向**历史（含助手回答）、跨渠道人生线程；修复记忆正则误伤；报告带真实日期与期间。

## 设计要求

### A. timekit（`mingjing_core/timekit/`）
- 把 `lunar-python==1.4.8` 加入 `requirements-core.lock`（纯 Python，带哈希锁定方式与现有锁文件一致）。
- `calendar_cn.py`：
  - `day_status(date) -> DayStatus{kind: workday|weekend|holiday|adjusted_workday, holiday_name, is_off, source: builtin|override|unpublished}`。
  - 数据源顺序：`config/holidays/<year>.json`（holiday-cn 格式：`{year, papers[], days:[{name,date,isOffDay}]}`）> `HolidayUtil` 内置 > 都没有则 `unpublished`（年份 > 已知最大年份时）。**`unpublished` 年份的日期只能按普通周末/工作日给出，并在 `source` 标注，绝不推测调休。**
  - `next_holiday(from_date)`：若下一个假期所在年份未公布，返回法定节日的固定日期（元旦 1/1、劳动节 5/1、国庆 10/1；春节、清明、端午、中秋用农历/节气计算）并标注 `arrangement_published=false`。
  - `tools/update_holidays.py`：从一个**可配置的本地文件路径或自托管 URL**（不要默认直连 GitHub/jsDelivr，服务器在国内）读取 holiday-cn JSON，校验后写入 `config/holidays/<year>.json`，打印差异；不在对话时联网。
- `almanac.py`：`almanac(dt, tz) -> Almanac{solar, weekday, period(凌晨/早上/上午/中午/下午/傍晚/晚上/深夜), lunar(年干支/生肖/月/日/是否闰月), ganzhi{year,month,day,hour}, jieqi{current,current_at,next,next_at,days_to_next}, festivals[], yi[], ji[], chong, sha, xiu, zhixing, zi_hour_note}`。
  - 晚子时（23:00–24:00）必须在 `zi_hour_note` 说明所用口径（lunar-python 默认不换日）以及"部分流派此时已换日"。
- `now_block.py`：`render_now_block(owner_settings, clock, last_interaction_at, upcoming_events) -> str`，格式**逐字段**对齐蓝图 §5.2；时区取 owner 设置 `timezone`（默认 `Asia/Shanghai`），把 `core_owners.settings` 增加 `timezone` 字段（迁移内或代码默认值均可，写进 Decision Log）。
- 把 `consultation.py:26 SHANGHAI` 与业务代码中直接 `datetime.now(...)` 的地方改为 `get_clock()`（P0 已列清单）。
- 测试：用 07 附录的每一行做参数化测试（日期、星期、农历、日柱、节气、假日状态）；T 类场景所需的全部字段都要有测试；2027-01-01 与 2027-02-06 必须返回 `arrangement_published=false`。

### B. 迁移（只前进）
- `0005_agent_runtime.sql`：按蓝图 §15（先查出 `core_runs` 上 `CHECK(calls>=0 AND calls<=call_limit)` 的实际约束名再删除，改为 `CHECK(calls>=0)`；新增列与索引；新表 `core_run_steps`、`core_run_events`）。P2 只建表，不使用。
- `0006_threads.sql`：消息的 `thread_id`、`at_ms` 表达式部分索引。
- `0007_search.sql`：`search` 生成列 + GIN 部分索引；`core_embeddings` 表与删除触发器（实体 `status='deleted'` 或 `data='{}'` 时删除对应向量行）。
- `repositories/postgres.py`：

### C. 人生线程与助手消息
- `MemoryService.record_assistant_message(owner, subject, thread_id, text, *, run_id, kind='chat', used_fact_ids=(), channel, at)`：写 `message` 实体（`role='assistant'`，`origin='system'`），允许新 revision（`receive` 当前禁止改内容，`memory.py:80`，不要改它的语义，新开方法）。`save_fact` 仍拒绝非用户来源（`memory.py:184`）。
- 所有新入站消息写 `thread_id = life:<subject>`（无痕除外，P3 实现）、`at_ms`、`channel`；保留原 `conversation_id` 为 `origin_conversation_id`。
- v3 `_phase_commit`（`consultation.py:941`）成功后调用 `record_assistant_message` 写入答案（`answer` 字段文本，`kind` 依 run 类型）。
- `tools/backfill_v4.py`：`--dry-run`（只打印数量与样例 ID）/`--apply`：给历史消息补 `thread_id`、`at_ms`（时区解析复用 `adapters/web.py:31-38 history_instant`）；把历史成功运行的答案回填为助手消息（跳过已撤销来源、跳过被删除的运行）；幂等（可重复执行不重复写入）。
- 搜索分词：`memory/tokenize.py` 用 jieba（加入 core 锁文件）+ 自定义命理词典（日主、喜用神、大运、流年、十神、正官、七杀、食神、伤官、正财、偏财、正印、偏印、比肩、劫财、化禄、化权、化科、化忌、命宫、身宫、上升、月亮、太阳、相位、合盘、逆位……），写实体时生成 `data.search_tokens`；回填工具同时补齐旧实体的 tokens。

### D. v3 速赢（现网行为改进）
1. **此刻块**进入 v3 的 intake 与 synthesis payload（字段名 `now`，内容为 §5.2 文本）；review 与 repair 继承 synthesis payload。
2. **历史**：`snapshot()` 改为按人生线程取最近 30 条（用户+助手，降序取再正序排列），每条带 `at`（owner 时区格式 `YYYY-MM-DD HH:MM`）与 `channel`；payload 的 `recent_history` 改为 `[{role, at, channel, content}]`，截断上限放宽到 4000 字/条；`CORE_INPUT_BYTES` 默认提高到 400000（用户不在乎 token；超出时仍按旧顺序裁剪）。
3. v3 的 `SYSTEM_POLICY`（`consultation.py:27-39`）增加两句（版本记录在 run meta）：
   "reference_data.now 是此刻的真实时间与历法信息；涉及日期、星期、节假日、节气时以它为准，并写出具体日期。"
   "recent_history 中 role=assistant 的是你之前的回答，用户说'那个/第二个/上次'时据此接续。"
4. **记忆误伤修复**（`memory.py`）：
   - OPTOUT：`别忘了记住/别忘记/不要忘了/不用每次提醒…记住` 不算拒绝；为 `memory/policy.py`（新文件，v3 的 `memory.py` 调用它）写正例、反例各 ≥ 15 条。
   - 假设句：窗口改为"所在分句"（以 `。！？；，\n` 和问号分界），"你觉得呢？我不能上夜班"应可保存。
   - 第三人称：改为词边界匹配，"其他的""我和他是同学"不触发。
   - 授权词：允许出现在事实之后的同一条消息里（"我下周三面试，请记住"）。
   - **不改变**敏感类别策略（那是 P5 的事），只修误伤。
5. **危机热线（安全速赢，优先上线）**：P0 实测 S01 显示 v3 给危机用户的是旧热线号码（400-161-9995、010-82951332），没有给全国统一心理援助热线 **12356**（2025-05-01 起 31 个省份全部开通）。
   - 新增 `config/crisis.yaml`：`hotline: "12356"`，`emergency: ["120","110"]`。
   - 在 v3 的 `SYSTEM_POLICY` 中加入："用户流露自伤、轻生或危险时，先关心并确认是否安全，提供全国心理援助热线 12356，紧急危险时拨打 120 或 110；不要提供其他热线号码。"
   - S01 必须通过。
6. **报告**：`adapters/channels/reports.py:62-71` 生成时传 `selection.date` 与 `period{start,end}`（用 `domain/report_schedules.py report_period`），消息文本也写清期间。

## 验收标准

1. 时间引擎单元测试覆盖 07 附录全部行；T 类场景所需字段齐全。
2. 迁移 0005–0007 在空库与"已有 0001–0004 + 合成数据"的库上都能执行；`verify_schema` 新测试通过；授权脚本 dry-run 覆盖新表。
3. 回填工具 dry-run/apply 在合成 300 轮历史上正确、幂等（跑两次结果一致）。
4. 1 万条消息的合成库上 `snapshot()` p95 < 150ms（给出测量方法与数字）；`list(order='desc')` 取到最新消息。
5. v3 实测评测（真实模型，本机隔离库）：T01–T08、T10、T11、T13 至少 9 个通过；R02、R03、R06 通过；M03、M09、M10 通过；与 `baseline-v3.json` 对比表入库。
6. 旧 Core 测试与旧前端测试全部保持通过（或在 Decision Log 写明哪些测试因"历史现在包含助手消息"而合理更新）。
7. **stage 上线准备**：写 `docs/v4/release/P2_stage_plan.md`（基于 `docs/CORE_V3_RELEASE.md` 与 `tools/deploy_core.py` 的流程：备份 → 迁移 → 回填 dry-run → 回填 apply → 冒烟检查 → 回滚步骤）。**执行 stage 部署前必须得到用户明确授权**；生产切换另行授权，并在大脑验收通过之后。
8. ExecPlan 与阶段回执完成。

## 何时停下来问用户

- 需要 stage 服务器访问或部署授权时；
- 回填 dry-run 在 stage 上发现数量异常（例如助手消息回填数远小于成功运行数）时；
- 需要决定 owner 时区默认值以外的设置时。
