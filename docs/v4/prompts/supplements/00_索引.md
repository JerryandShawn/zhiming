**上下文守卫（D2 附加要求，归主线 P3）**：
- 用户的所有对话都在一条人生线程里，但模型每次只拿到 ContextEngine 装配的分层上下文（目标约 3 万 token），完整历史保存在数据库，通过摘要和检索按需取用。
- 硬上限：单次请求输入 ≤ 180,000 token，约为 `k3-256k` 上限 262,144 的 70%，为输出和推理留出余量；超过 120,000 token 时，自动压缩较旧的层（L5 合并进摘要、L4 降低 K、工具结果改为"摘要 + 别名"）。
- 每次调用把输入 token 数写入用量账本。线程上下文连续 3 次超过 60,000 token，在汇总里提醒。
- 测试：R07（300 轮）与 1 万条消息的合成线程，都必须稳定在硬上限以内，且关键约束不丢失。
