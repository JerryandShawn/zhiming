# U9 出生范围交节细化

2026-10-18。补齐“十二时辰中心点距节界都超过两分钟，却在声明范围内发生交节”的缺口。原先中心点的近节探测不足以覆盖未知全天或较宽区间；现在根据声明范围独立枚举真实节界。

`jie_uncertainty.boundaries_in_range` 将明确的出生民用时间范围按已提供UTC偏移换成UTC+8历法时间，从范围下界前1秒调用锁定 lunar-python 的 `getNextJie` 逐次推进。只查询“节”，没有把中气加入月柱分界。枚举最多8步，遇到非前进或缺失下一节明确报错，不跳过。范围不超过48小时。

每个范围内节界生成严格早于边界的分钟点、严格晚于边界的分钟点：非整分钟界点取所在分钟和下一分钟；整分钟界点取前一分钟和后一分钟。两个点分别裁剪到声明范围，绝不扩大未知/大概/区间所声明的出生范围。若范围边缘只容纳一侧，`strict_sides_within_declared_range` 说明哪侧缺失，不以界点本身冒充严格“之前”。

`RectificationEngine._jie_samples` 对每个唯一声明范围查询上述节界，保留原始采样并加入去重后的两侧点。未知时间的非交节日仍有十二候选；交节日可以更多，此时每个候选明确携带 `sampling.kind=jie_refined_sampled_not_continuous`、原始/实际候选数、完整范围及节界。`random_three_baseline=min(3,N)/N` 指对显示的采样时刻均匀随机取三的基线，不是对十二时支的均匀分布，更不是出生时间的概率；短范围两候选的基线为1。owner/subject/revision范围仍由原有calculate阶段统一绑定，新增候选也不会绕过。

真实引擎回归使用2026立春和惊蛰：锁定引擎立春为2026-02-04 04:02:08（UTC+8），普通全天十二中心点均不在±2分钟内，细化后保留04:02和04:03两侧。2026惊蛰为整分钟边界，在只声明21:58至21:59的范围中仅补/保留严格之前的21:58，不越界加入22:00。春分为中气，全天不新增节界候选。另覆盖UTC偏移-5及+14对应的不同民用日期、较宽大概区间、原输入不变及公开计算的归属/推断状态。

独立测试文件 `tests/test_p8_rectification_jie_native.py` 有10项真实Charts测试，对应Core桥 `tests/v4/test_p8_u9_jie_process.py`；原25项文件不改。最终验证结果与实际数量见 `u9-validation.json`，Core两桥输出见 `u9-bridge.txt`，公开历法例子见 `u9-jie-range-examples.json`。原十人合成fixture和评分权重保持不变，最终指标及新方法SHA见 `u9-synthetic-evaluation.md`；没有把新增有限采样写成连续区间已完全稳定。
