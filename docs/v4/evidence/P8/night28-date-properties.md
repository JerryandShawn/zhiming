# 28 号日期与逐日工具属性检查

入口为 `mingjing_core.adapters.charts.benchmarks.night28_date_properties`，必须显式 `--mode scripted`；没有 live 模式。`--suite random|annual|all` 可分开运行，固定种子 `20261020`。脚本清凭据、关追踪，并使用现有离线上下文阻断网络；Windows 的本地平台信息缓存在进入白名单约束前预热。报告按 UTC+08:00 写生成时间，列出产品代码、研究脚本与实际 IANA 区文件摘要。

随机部分设计为 **1000 个去重的合成民用日期**，四层各 250：1986–1991 的夏令时年份、负月份表示的农历闰月、十二节交接日前后、真太阳时晚子/午夜交界。另有 12 个单列的确定性 DST 缺失/折叠锚，不冒充随机1000日期的一部分。没有从真人出生资料采样。

每条检查包括：

- 物理 UTC 去重、钟表/标准时往返、同一瞬间三种口径完整保留、夏令时缺失不平移与折叠两次保留。
- 日差与五鼠遁独立算式核对日时柱；真太阳钟坐标必须等于 UTC 加经度修正加已报告均时差，防止重复改 DST 或经度；同一瞬间的年、月柱跨口径一致。
- 冲支按日支加六取模十二、煞方按日支三合组的独立有限算术；黄历实际字段和内容依据别名完整。
- 时辰、晚子、午夜临界带用独立钟点取模算术核出，既不能漏提示也不能超带提示；节界两侧柱变化按明确已安装库核对。

逐日部分设计为 **2026-01-01 至 2027-12-31 全部730天**：每一天实际计算 daily_transit，实际调用公开 window_search 入口的一日区间，六用途轮换；每月第一天额外运行当月多日排序的一页，以检查全区间摘要、全局排序和页内依据。不是用返回结构的桩或日期列表冒充计算。

daily 显式北京时间正午及 UTC 04:00、日干支计数、全部相位成员集合与容许度、依据内容摘要均受检查。西占几何用圆周最短距离重新计算所有本命/行运天体对，避免只检查已返回条目而漏掉本应纳入的相位。window 核对完整排序、正负贡献合计、页选择、局部 c/r 和摘要哈希；同一日的 daily 在 UTC 环境、window 在 Tokyo 环境，逐项比较来源内容。不会修改 Windows 系统时区。

## 证据分类与待核

日差与时干是独立算式，但甲子锚 `2000-01-07` 仍先由已安装历法库核对；**不是独立历史历法真值**。闰月、节交接的样本和核对都共用该库，只能称库一致性。时区往返共用已固定 IANA 数据，不能代替出生证或证明历史时区记录无误。西占独立几何核对共用同一历表黄经，不证明天文位置的外部准确性。

黄历 sect1 的民用日/月标签与 daily 的精确节界月不是同一口径，不能强行断言其月柱每时刻相等。宜忌、值神与建除可能有不同体系的标签，未作“所有文化标签必须一致”或“正分必然成功”断言。原刊版本、纸页、六破出处和四化异表按 M4 保留待核。

小型专属回归只演练20个去重随机日期和12个DST锚，避免每次完整测试重复跑长研究；完整1000日期与730天的结果由单独带指纹报告给出。未取得报告前不得把脚本可运行当作全部通过。
