# U9 时辰校正合成评测

本报告只检验确定性规则内部的可逆性与排序实现，不验证真实人生预测或现实中的时辰校正准确度。全部人物、来源和事件为合成数据；未调用模型、未读真实记忆、未写出生资料。前端/飞书事件确认、主线资料确认事务、`rectified` 枚举持久化不在本计算测试中。

## 预先固定的设定

代码 `mingjing_core/adapters/charts/rectification_evaluation.py` 固定十个合成人物：1960至1978年，每两年一人；固定月日、经度、UTC偏移、性别和已知地方平太阳时辰。首次计算前已将较晚年代方案改为1960–1978，以保证18/25/32岁事件均在1978–2010的过去；之后没有按分数换人、换时辰或筛掉样本。

固定 fixture SHA256：`c4f68bf9cd647083a4fa6b0ced418533c552b6aeb63887a7ecf278a22396348a`。固定UTC偏移只是合成计算输入，不代表相应经纬度的历史夏令时已核实。

每人固定三个事件时点：出生年加18年6月、加25年9月、加32年3月。生成器仅看已知时辰那一盘，在登记的八类事件中选该时点当前项目规则分数最高的类型，同分按类型字典序选取。它不查看其他候选的排名。来源标识统一为 `synthetic-source:*`，完整生成依据、各备选类型分数及盘面交互保存在 JSON。`user_confirmed=true` 仅模拟测试中“事件已经确认”的输入状态，不冒称真实用户记忆。

盲排请求只传出生日期、未知时辰范围与三件生成事件，不传已知时辰或正确候选标签。引擎对全部十二候选逐一重算；核对时用已知候选的民用时刻匹配带 owner/subject/revision 范围的候选ID。没有全球跨owner缓存，也没有为了节省时间跳过候选。

## 分数与并列

项目评分每事件最多2分：象征主题吻合1分、结构触发1分，同事件多条关系不叠加。该分数不是古籍公式或概率模型。三事件满分6分。

稳定展示前三按分数、民用时刻、ID排序；同分的时刻先后顺序没有准确性意义。因此同时计算 tie-aware 指标：若正确候选前有 `better` 个更高分，同分组有 `tie` 人，随机打散同分后进前三的概率为 `min(1,max(0,(3-better)/tie))`。例如十二候选完全同分时，无论稳定顺序是否显示正确时辰，这个概率都是25%。

修正事件时间分段后的最终十人全部完成，十二候选/人：稳定前三5/10（50%）；随机解并列后的期望为3.5513/10（35.513%）；无信息时十二取三随机基线为25%。十人均有正确分数并列，其中六人十二候选全部并列。不能把50%写成现实命中率，也不能据此宣称统计显著高于随机。修正的是月中取样不足以代表整月的问题，没有调整评分权重或筛选人物。

## 循环性、限制与复查

用评分规则生成事件，再用相同规则反推，存在明确的循环性；选已知盘最强类型还引入选择偏差。即使这样，当前评分仍出现大量并列，区分能力有限。这一结果适合检查工程实现并暴露规则信息量不足，不能证明用户出生时间已被确认，也不能通过调权或挑样本来包装为高分。

月未知时引擎按公历年范围、出生日期、立春、农历新年及交运边界分段；月已知时另按交节分段。片段中点仅是代表，明确 `not_event_day=true`，不同片段分数取保守最低及最高范围。当前年度或月份的片段截止到调用方传入的 `as_of_date`（包含当日）；不读取主机当前时间，不把未来片段当已发生事件。未使用流日，因此不宣称事发日或真实因果已确定。出生时间为区间时仍仅有限采样。亲人变故、健康类型只回顾已确认事件，不推断将来的灾病或死亡。
