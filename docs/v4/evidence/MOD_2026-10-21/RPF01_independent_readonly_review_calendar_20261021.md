## 接受面与输出边界

| 边界 | 静态核对及已验证行为 | 限制 |
| --- | --- | --- |
| 类型 | 22 个注册 dataclass 使用精确身份；标量和容器同样使用精确类型 | 未知类、子类不在接口范围；不是旧泛型助手的完整接受面 |
| 类注册表 | 只缓存类引用和字段名；身份键不调用外来元类相等/哈希 | 没有缓存正文、权限、时钟或投影结果 |
| 容器 | 每次生成新 dict/list；共享但无环的输入节点按各边分别复制 | 不保证保留别名关系；并发修改输入不受支持 |
| 循环与深度 | 当前递归路径身份集合检测环；深度上限 64 | 深度不是总节点数或字节预算，超宽图仍需 host 限额 |
| 数字与日期 | 非有限浮点拒绝；精确 date 转 ISO；标准 aware datetime 转 UTC | 无时区、自定义时区、不可复制的 from_file ZoneInfo 保守拒绝 |
| 时区 | no_cache 标准 ZoneInfo 的两个 DST fold 独立同值 | 复制检查成功不证明未来 tzdata、全局复制注册表或并发环境改变后的等价 |
| 文本 | 保留 Unicode 原值，不做规范化；原 digest 继续执行 JSON/UTF-8 边界 | Python str 本身不保证 UTF-8 可编码；孤立代理字符可能到 fingerprint 才被拒绝 |
| 错误 | 候选错误使用固定 ProjectionError 原因 | 不承诺与旧链路所有异常类别相同，也不提供任意 Python 代码隔离 |

在已经覆盖的 22 类合成形状和当前固定运行环境内，可以比较 JSON、fingerprint、输入不变及输出容器独立。
这不证明任意 Python 对象都等价。即使值嵌套在注册 dataclass 中，其子类、自定义时区等仍须满足上述更窄约束。

## Hook 与 oracle 独立性

基准仅在独立进程临时替换反思模块 `validation`、`intent_guard`、`summaries`、`work` 的四个投影别名。
进入前检查四者都是保存的原 oracle，退出 finally 恢复并验证身份，异常退出恢复也在语义检查中覆盖。
没有修改旧反思文件，没有替换 Q2 或 U4 的函数。

旧 oracle 的递归调用会动态读取 validation 的别名，因此在 hook 内调用它不能当作纯旧实现对照。
现基准显式在 hook 外完成 corpus 对照，并在恢复后比较 baseline 与 candidate 的语义捕获；
已核对该次序，未发现当前测量中的 oracle 混用。

hook 没有线程级隔离或锁，其他线程可能观察临时别名。它只能用于该独立、无并发工作负载的实验进程，
不能直接放进真实服务。别名恢复和序列化等价也都不是当前来源、撤回状态或用户授权的替代品。
