## 可执行接口

`seed.profile` 引用 `fixtures/profiles.yaml`；`profile_overrides` 递归覆盖资料，用于未知时辰和出生区间。
`seed.facts` 使用业务类别 `kind`，投影到观测结果时统一为实体 `kind: fact`、`data.kind: <业务类别>`。
`seed.entities` 已是 `{id, kind, status, data}` 形状；`settings/context/controls` 分别承载设置、上下文和故障注入配置。

每个 `scripted` 项显式对应一轮；模型动作可以是文本、工具调用、工具结果、回执、DB 快照、事件或元数据。
DB 动作只覆盖显式给出的快照键，`entities` 列表为该键的完整快照；不能从 `expect` 自动制造返回结果。
`expect` 只负责检查：文本同义备选、工具正反条件、回执子集、实体计数/状态、路径值/包含/缺失、数值范围和事件顺序。
问题数量按最终文本中的中文或英文问号计算。这个机械检查不替代评审模型对自然表达与提问质量的评价。

X04 使用 `0 <= stop_latency_ms <= 2000`，L02 使用 `0 <= score_spread <= 0.15`，避免把固定样本观测值误当正确实现。
v3 的资料初始化事实应与正文记忆断言区分：M04 的“事实数为零”针对正文记忆，不能把画像初始化行混入计数。

## 校验

本机 `.venv-core/Scripts/python.exe` 运行 Schema 与逐场景 `evaluate_scenario(..., FakeTarget())`：

    80/80 exact documented IDs
    80/80 deterministic replay
    80/80 repeated replay identical
    7/7 malformed schema mutations rejected

七类负例为未知字段、无时区时钟、ID 与分类不符、重复目标、错位回放轮次、空断言、助手原话作为用户事实。
命理合成画像的日柱另用本机 Charts 环境 `lunar-python` 核对，1994-03-12 08:20 的日柱为丁酉。
完整框架测试与正式 scripted 报告由框架任务统一运行并保存，本文件不将独立校验冒充真实模型或 v4 业务验证。

## 设计歧义与边界

T14 已按大脑第 11 份复核定稿：问题为“我这周还有什么安排吗？”，必须说清 10 月 21 日在下周，
禁止说成“这周三/本周三”；本周截止 10 月 18 日周日。此项歧义已解决。

M11 原文允许保存 concern，也允许将推测写为 inferred note。断言检查“不把推测变成事实”，不强制唯一存储实现。
Q04 只禁止重复询问已知偏好，允许询问其他未知信息；Q06 允许澄清或识别地点变更，不强制一定发问。
C03 只在确有流派分歧时要求并列；初次转写中三处过度约束已按原文修正，未迁就任何被测实现。

C03 按大脑复核只检查有效盘面引用、至少一种口径或流派与非绝对表达，不设置喜用神或五行固定答案；
规则缺口不能通过。C06 已用 Charts 隔离解释器真实计算五点与两个边界探针，金标固定在
`tools/eval/fixtures/c06_ziwei_golden.yaml`。命宫主星采样不一致：地方平太阳时寅时为紫微、破军，
卯时为天机，纠正初始回放把民用时间直接当成卯/辰的错误。详见 `chart-goldens.md`；独立来源交叉核对留 P8。

L01 是四种模型的工具协议矩阵，L02 是多份实测报告的分类分差聚合；二者不是普通单轮咨询。
P0 只提供合成动作与断言接口；真实四模型循环与分差未运行，应在后续模型接入阶段实测。
X03 的崩溃、X04 的停止时延及 X08 的重连在 fake 中也是观测回放；真实进程、墙钟和网络验证留待相应阶段。

本子任务没有真实模型调用、真实飞书投递或业务数据库迁移；没有声称 v4 功能或人生预测已经验证。
