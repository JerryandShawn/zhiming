# Z1 / Z2 离线服务级证据与主线接线口

北京时间 2026-10-20 夜间。执行期间无服务器、SSH、模型请求或飞书发送。该片不是 P3 全阶段验收。

## 已实施

- 公开 K3 计数可信注入接口；本机词表和 encoder artifact 分别核版本与 SHA-256。没有配置就拒绝，没有下载、新依赖或另造 tokenizer。
- `ceil(estimated_input_tokens × factor)+4000` 估算上界，默认 factor 1.15；既有 120k 压缩与 180k 硬拒绝保留。完整规范化请求的工具、参数、推理与签名均送计数 seam。
- 供应商 actual 从已完成 PG 模型步骤读取，独立保存。actual 超原 upper 时写 `input_token_upper_bound_exceeded` 告警，以 `actual/estimate×1.1` 自动升系数，按线程 / tokenizer / encoder / provider / model 身份持久保存。未知 actual 保持 null，零 estimate 不伪造除法结果。
- L5 发送前 metadata-only 预留、epoch / generation、缓存前缀 hash、同周期 append-only 校验；压缩 / 有效源变动 / 撤销换周期。L0+L2+L3_STABLE+已发 L5 的 canonical message fragments 定义应用缓存前缀；不包含易变块。
- `mark_sent` 同事务核租约 / retry epoch、真实 Journal 步骤 fingerprint、来源版本及撤销、当前预算实际 prefix、线程代次；与 usage 共用线程锁。重复同一步不加代次，并发同一旧代次仅一个提交。

- Z1+Z2 pure / PG / 旧层次及来源 / 合成长 token 压力：`126 passed in 10.69s`。
- 新增压缩幂等与估算标签反例后的最终复测：`128 passed in 14.77s`；Ruff E,F,I,B,UP,SIM 与 format120 通过，12 个新增 / 修改 Python 文件最大 179 行、无函数超过 60 行。

## root 的 Loop 接线顺序

每次**物理模型请求**，而不是只在 prepare_context 时：

1. 从 `ContextUsageService.factor(owner, subject, thread_id, meter_identity)` 取该身份最近因子，构建 / 更新受信 `K3EstimatedMeter`；缺 encoder 拒绝。离线 scripted meter 保持 `live_admissible=False`。
2. `_budget()` 得到包含本轮 CYCLE 的完整 `budget` 和 tool_choice；执行 180k 门控，人工在线批次 / 中央 HTTP 守卫继续独立校验。
3. 用 `ContextEpochService.preview(owner, subject, thread_id, budget, frozen.injected_versions, frozen.snapshot_revision)` 产生新计划；`replace(frozen, budget=budget, cache_epoch=plan)` 得发送上下文。必须每次重取 generation；旧 plan 不可直接用于下一次物理请求。
4. 按现有 Loop 的 messages/tools/tool_choice/source_versions 生成 Journal input_fp 并取得 step。已完成 step 走重放分支，不重新发送。
5. 未完成分支在端口调用**之前** `ContextEpochService.mark_sent(step, send_context, tool_choice=choice)`；预留失败即停止 / 重建，不发送。mark 不访问模型，不跨 HTTP 持锁，receipt 的 `send_reserved` 不能解释为远端已收到。
6. 真实返回后 `completed = journal.complete(step, assistant_output, response.usage)`；随后 `ContextUsageService.record(completed, budget.meter)`。重放完成步也可 record，按步骤幂等，不重复升因子 / streak。

重放计量必须对应该步骤**原来**的 preflight；已经校准的新因子不能回写旧步骤计量。`record` 对同一步不同 preflight 会拒绝，原始三项计量和其 fingerprint 应随步骤恢复，或者只读使用已存 receipt，不触发再次发送。

若 `_budget` 因 CYCLE 增长进一步压缩 L5，要用**压缩后的真实 budget** preview；mark 会拒绝 plan 与实际发送预算不一致。

## 未完成 / 限制

- 本片未改 `loop_cycle.py`，上面接线尚待 root 实施及端到端测试。
- Core 锁环境未安装公开 K3 encoder；旧研究结论不足以自动启用任意本机词表。`PinnedK3Counter` 是待可信应用绑定真实 encoder 的 seam，替身 hash / 计数测试不等于真实 K3 准确率。`live_admissible` 默认 false，不能靠构造文档宣称已验证真实端点。
- 新周期持久服务按当前 ContextEngine 的人生线程支持范围实现；无痕线程不持久化此元数据，需 M5 接线另证。
- token 上界是 Z1 接受的**估算上界**，不是 framing 等价或供应商绝对安全证明；actual / 告警 / 系数用于后续观测。没有真实 token 或缓存命中率结果。
- 原型压力仍采用明确标记的 synthetic / policy_units 计量；原话 PG 完整性与读取上限可据其验，不能据其宣称真实会员 180k token 已测。
