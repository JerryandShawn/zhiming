# E2 M2 控制输入接线契约（离线草稿 v1）

本契约落实28号M2，与历史C0–C4协议并存。它只规定离线输入与评分隔离，不授权真实模型请求。
当前14道2025赛季纳入题、66道排除、9个源内案例及固定种子20261020均保留；专业分数为null。

## 两种控制各用什么

| 控制 | 当前纯入口 | 必须保留 |
| --- | --- | --- |
| 宽松安慰剂（同源跨案例） | `benchmarks.night28_controls.same_source_placebo(records, seed)` | 只换birth；同源、跨不同案例、不同出生、一对一供体，同案例多题共用同供体；允许跨题目目标年 |
| 无盘对照 | `benchmarks.night28_controls.no_chart_input(record, seed)` | 只输出原题和置换后的四选项；不含原ID、出生、派生盘、答案、解释或历史 |

宽松控制没有放宽明确题面目标年、标签完整性和重复题身份检查；选项/答案映射保持评分侧。
固定匹配有2/14供体出生晚于原题目标年，因此只有结构可构建，不能报告14对完整可排盘。
在大脑裁定前不换seed、重抽、删题或改变分母，主线实际评测必须保留阻塞并停止相应完整质量结论。

## 无盘模型可见输入

[JSON Schema](e2_m2_no_chart_input.schema.json)为draft2020-12，严格只有以下两键。
下例是独立合成结构样例，不是专业题目或测得成绩：

```json
{
  "question": "合成练习：只根据给定信息选择一个选项。",
  "options": {
    "A": "合成选项甲",
    "B": "合成选项乙",
    "C": "合成选项丙",
    "D": "合成选项丁"
  }
}
```

`options`的显示标签为A/B/C/D，具体内容沿用原题，按固定种子及原题身份确定性置换。
主线只能把这个两键对象序列化给无盘推理；不能发送完整Question、RequestV2、rehearse报告或评分记录。
种子、供体、原题/案例身份、gold、显示标签→原标签映射、目标年判定和控制组标签均留在评分侧。
即使对其中字段作hash，它们仍不属于此模型输入allowlist。

无盘输入没有实际排盘或命中，因此不生成〔c#〕/〔r#〕，也不能伪造空盘依据。
后续若回答引用命理规则，不得据此认为该控制收到了计算依据。

## 与旧 C0 的区别

历史`protocol_v2.RequestV2`的C0表示“不提供派生盘”，仍有`birth.public_input()`；
它的question还保留question_id以及显式目标年信息。该语义不等于本轮两键无出生控制。
对BaziQA，旧C0还可能逐题累积同案例history；新M2两键对象不携带这类历史。
旧C0本轮未修改；主线不能仅更名configuration或清空chart_bundle，就把它报告为M2无盘。
这里列的是静态接线区别，当前未执行真实传输，不声称已经发生模型泄漏。

## 评分侧与拒绝边界

评分侧保留原问题、gold及置换逆映射；显示答案A/B/C/D先映回原标签，再由原题gold评分。
复用`controls_v2.shuffle_options(record, seed, 0)`的第二返回值：键为显示标签，值为原标签。
`no_chart_input`当前固定trial=0；评分侧不能另换trial、seed或按选项正文排序来反推。
不得把答案/评分提示塞回input；同案例历史与专长输出不注入无盘组。
原始题文和选项不能因控制组而改写，模型看不到两组出生的差异。

额外顶层字段、非A/B/C/D选项、缺项、非字符串或空白文字均为Schema拒绝。
Schema只约束结构；它不证明题文没有出生暗示、答案暗示、相近题相关性或训练集污染。
原题本身可能带线索，应该另做只读审计，不能自动删原文或改变正式基线。
来源/年份有歧义或BaziQA缺标签继续按纳入清单排除，不以Schema通过重新纳入。
