## 词条结构

| 字段 | 含义 |
| --- | --- |
| `term_id` | 稳定标识，带bazi/ziwei/astro/tarot前缀；不能因显示次序变化而重编号 |
| `system/term/aliases` | 体系、主名称、明确同义名称；同一体系内不另建同义重复词条 |
| `definition_kind` | 区分传统概念、天文时间坐标、几何参数、象征推运、原创象征/编辑方法与项目约定 |
| `plain_explanation` | 项目原创白话，讲清这个词指什么及必要边界；不据术语给用户定性 |
| `example` | 独立、具体的小例句或合成算例；不假设用户生辰，也不编现实应验 |
| `sources[]` | source_id、该词具体locator、该来源究竟支持什么；不可将方法出处偷换成预测效度 |
| `school_differences[]` | 具名方法/流派的差别与source_ids；没有把握时保留差异待核，不编某门派立场 |
| `pending_review[]` | 原刊版页、方法完整性、适用范围或现实效度等具体未核项 |

来源注册记录title、kind、url或本仓库path、locator、verification_status及edition_page_status。
项目代码定位只证明项目如何计算，不能替代古籍原文；官方程序文档只证明该作者/库的口径，不能代表各流派共识。
同一词条可同时引用实际实现和历史概念，但须分别写支持范围与核实状态。
版次、页码不知道就写待核；网页段落序号不冒充纸页。
塔罗现有原创牌义保持原创署名，不改标为Waite逐句翻译。

经独立复核补齐具体定位：年/月柱指向`time_basis_candidates._candidate`的物理节界，
日柱/晚子时指向声明坐标`setSect(1)`；阴刃异说同时给出`schools.json:/blade`
实表和`named_bazi.named_stars`执行层，逆行第三说的古籍归属仍待核。
伤官牵制与庚辛例外指向`p8_structure.restraint`，不靠通用十神算式充当依据。
容许度的6/6/2默认值分别定位本命、合盘和流日实际函数；等宫制说明精确Ascendant
每30度起宫，本P8当前未实现该可选制。现有legacy文件仅只读查证。

当前36个来源中，31个为本地实现/项目原创文件，本轮已核实际路径和相关定位；
5个URL沿用此前阅读记录，本轮未再次外访，不把URL存在或Schema通过当作重新原典核验。

## 前端 / 对话的读取约定

这是数据契约，**本批没有声称实现搜索API或对话弹窗**。
前端或主线可加载两份JSON，在内存按system筛选、以term和aliases做搜索，点击term_id显示原词条及来源。
exact match不能改写词条含义；未命中时返回未找到，由调用方提示，不让模型临时补一个有权威出处的词条。
同一术语跨体系重名时保留多个候选并显示体系，不能按第一个搜索结果猜用户所指。
source_id不存在、版本不匹配、词条ID冲突或计数不一致属于数据错误，不自动隐藏后仍宣称词典完整。

术语解释是研习材料，**不是当前用户的计算依据或规则命中**。
不能仅凭词典自动生成〔c#〕或〔r#〕；若学习模式结合某次盘面讲解，必须另外绑定那份chart_compute的真实依据。
词典不授予排盘、更新档案、读取他人生辰或重新抽牌的权限，倒推仍冻结隐藏。

## 数据完整性与验收

seed阶段必须恰好10条且明确未完成，in_progress阶段必须保留未完成提示；
只有实际达到总数与四体系最低数、逐条编辑复核且测试通过后，
才能切换为 `draft_complete_200_for_review`，仍表示待大脑审阅的草稿，不是传统方法实证认证。

Schema检查字段结构和分阶段数量下限；专属测试另外检查：

1. 实际条数/分布与声明计数一致，稳定ID和规范化名称不重复，同义词不计作独立新词。
2. 每条都有具体白话、不同的例句、存在的source_id和定位，以及具名差异/待核。
3. 所有本地来源path指向仓库内真实文件，不能越目录；来源版本匹配，不通过URL运行外部内容。
4. 未满200时不冒报complete，来源不明时不冒报原刊已核。
