# 22 · 功能区设计：让对话和记忆分区存放，不再混成一锅（v4.3）

> 作者：Claude（大脑）　日期：2026-10-18
> 起因：用户和线上旧版"知命"的**所有对话都在同一个窗口**里，担心上下文不够用，也觉得所有东西混在一起太乱。用户希望把**原有的对话和记忆按功能区分类整理**，让以后的日常对话更有条理。
> 本文档：先回答"旧版现在会不会出问题"，再给出 v4 的"区 → 话题"结构、上下文策略、旧对话整理方案、各渠道界面，最后说明交给 Codex 的方式。

---

## 0. 先说旧版：现在不会"爆"，也不会丢

- **旧版不会因为对话太长而崩**。v3 每次只取最近大约 11 条你的发言给模型（`application/consultation.py:344`），所以从来不存在"上下文装满"的问题。它"忘事"恰恰是因为取得太少，不是太多。
- **你说过的话一条都没丢**，全部存在服务器数据库里（`message` 实体）。v4 的 P2 已经能把这些历史回填进"人生线程"，以后整理就从这里开始。
- **建议**：旧版里不要为了"分类"去点"新会话"。在 v3 里新会话等于让模型从零开始，忘得更多。照常在原窗口聊就行，分类交给 v4 一次性整理。

## 1. 结构：区 → 话题 → 消息

```
人生线程（底层：一条连续的时间线，保证明镜知道你的全部近况）
 ├─ 区：日常
 │    └─ 话题：随便聊聊 / 最近心情 …
 ├─ 区：事业学业
 │    ├─ 话题：跳槽（已升级为"事项"：有目标、跟进）
 │    └─ 话题：考研复旦
 ├─ 区：感情人际
 ├─ 区：家庭
 ├─ 区：身心（敏感区）
 ├─ 区：财务（敏感区）
 └─ 区：命理研习
      ├─ 话题：我的命盘（格局、喜用的讨论）
      └─ 话题：学紫微
```

| 概念 | 是什么 | 规则 |
| --- | --- | --- |
| **人生线程** | 底层只有一条时间线（P2 已实现 `life:<subject>`） | 保留不变：保证跨区的连续性。比如你在"事业"区聊天时，明镜仍然知道你昨天在"身心"区说过睡不好 |
| **区（space）** | 生活领域。默认 7 个（见 §2），可以改名、增加、合并、隐藏 | 每条消息、记忆、事项、塔罗记录都归属一个**主区**，可以有一个副区 |
| **话题（topic）** | 区里的一段具体的事 | 自动创建、自动起标题；14 天没有新消息就归档（保留摘要）；可以升级成"事项"（加目标、跟进）。**事项 = 有目标的话题**，两者统一，不再是两套东西 |
| **工具页** | 命盘、塔罗仍是独立页面 | 塔罗记录按问题内容归进对应的区（问面试的牌归"事业学业"）；塔罗页可以按区筛选 |

## 2. 默认 7 个区

| 区 | 放什么 | 特别规则 |
| --- | --- | --- |
| 日常 | 闲聊、心情、近况、没法归类的内容 | 默认区；分类没把握时先放这里 |
| 事业学业 | 工作、跳槽、面试、考研、技能 | — |
| 感情人际 | 恋爱、朋友、同事、人际矛盾 | — |
| 家庭 | 父母、亲人、家务事 | 涉及他人隐私时沿用"先问再记" |
| 身心 | 身体、情绪、睡眠、就医 | **敏感区**：主动消息的锁屏预览不显示内容；新记忆默认先问再记（与 P5 敏感策略一致） |
| 财务 | 收入、支出、投资、买房 | **敏感区**：同上；不做投资保证 |
| 命理研习 | 你的命盘解读、命理知识学习、流年总览 | 与"命理档案"（U3）联动 |

## 3. 自动归区：不需要你手动分类

1. **先在本地预判，不额外调用模型**（遵守 D1 的额度约束）：
   - 关键词规则加本地向量相似度（用 P5 的本地向量模型），和每个区的"区描述"、各话题的摘要做比较；
   - 当前话题有"粘性"：同一话题里接着聊，除非内容明显换了方向，否则不改归属。
2. **明镜可以纠正**：Agent 循环里新增工具 `topic_route(space_id, topic_id | "new", title?)`。模型觉得预判错了，可以在同一次调用里改正，不多花一次请求。
3. **你可以一键改**：每条回答下方显示一个小标签"归入：事业学业 · 跳槽 ▾"，点一下就能改区、改话题、新开话题。
4. 你明确说"这个放到家庭里""开个新话题聊买房"时，按你说的办，并记住这类偏好。
5. 同一条消息涉及两个区（例如"因为家里的事想换城市工作"），主区放"事业学业"，副区放"家庭"。

## 4. 上下文怎么分区（解决"上下文不够用"）

在 02 蓝图 §5.1 分层的基础上，按区收窄、加深：

| 层 | 原来 | 现在（分区后） |
| --- | --- | --- |
| L2 画像 | 全部条目 | 全部条目，但当前区相关的条目排在前面并附细节，其他区只保留一句话 |
| L3 进行中 | 全部事项 | **当前区**的话题与事项完整列出；其他区只列标题 |
| L5 线程 | 最近 30 轮（所有区混在一起） | **当前话题**最近 30 轮原文 + 当前区摘要 + **"其他区近况"一段**（最近 7 天每个区一两句，由沉思任务生成） |
| L4 检索 | 全局 | 当前区加权 ×1.5，其他区照样能检索到；约束类事实永远全局置顶 |
| L1 此刻 | 不变 | 不变 |

效果：
- 每次送给模型的内容**更少但更相关**，仍在 D2 的上下文守卫之内（约 3 万 token，硬上限 18 万）；
- 明镜不会因为分区而"只见树木"：其他区近况有摘要，约束类事实永远在场；
- 晨报汇总所有区。

## 5. 旧对话整理：一次性把你和旧版的全部对话分好区

**原则**：只**新增**区和话题标签，不修改、不删除任何原始消息；先出整理建议给你看，你确认后才生效；可以一键撤销。

1. **切段**：把旧版全部对话（你的发言 + P2 回填的旧版回答），按时间间隔（例如超过 6 小时）和话题转折（本地向量相似度突变）切成一段一段的"片段"。
2. **归区**：每个片段用本地规则 + 本地向量判定主区、副区，并给出把握度；把握度低的标"待你确认"。
3. **聚话题**：同一区内相似、时间相近的片段合并成话题，先用关键词自动起一个临时标题。
4. **记忆归区**：已有的事实、事项、塔罗记录、旧档案（时间线、人物、个人词典）按内容归区。人物进"感情人际"或"家庭"的"重要的人"。
5. **整理建议页**（"关于我 → 整理建议"）：
   - 每个区有多少话题、多少条消息，以及话题列表（标题、时间跨度、样例摘要）；
   - 你可以改名、合并、拆分、移动、忽略；
   - 按"应用整理"后才写入，每批生成 `batch_id`，随时可以撤销。
6. **起标题（可选）**：临时标题不好读时，可以点"让明镜帮我起标题"。只在你点击时调用模型，每次最多 30 个话题（这属于交互式使用，额度受 U38 守卫约束）。
7. **全程本地计算**：除了第 6 步，整理不调用 Kimi，不会触碰会员准则里"批量自动化"的红线。
8. **在服务器上执行**：先在 stage 的数据副本上跑一遍出报告，你看过报告后再授权在正式环境执行。

## 6. 各渠道的样子

**网页·桌面**
- 左侧栏"对话"展开后是区列表，每个区显示最近活跃时间和未读数。
- 点进一个区，中间是话题列表，右边是对话。
- 顶部有"全部"视图：按时间看所有区。

**网页·手机**
- 对话页顶部是一排可以横滑的区标签，下方是话题下拉选择。
- 输入框上方自动显示"将归入：事业学业 · 跳槽"，点一下就能改。

**飞书**（天然只有一个聊天窗口，所以全靠自动归区）
- 每张回答卡片底部有一行小字"归入：事业学业 · 跳槽"，附两个按钮［改区］［新话题］。
- 可以直接说"这个放到家庭里""切到感情""开个新话题聊买房"。
- 晨报按区分段。

**关于我**：记忆按区分组展示，每个区下面列出"重要的人"和事项。

## 7. 数据与接口（给 Codex 的要点）

- 新增实体 `space`：`id`、`name`、`description`、`sensitive`、`order`、`hidden`、`revision`。
- 新增实体 `topic`：`id`、`space_id`、`title`、`status`（open / archived / case）、`summary`、`summary_until_message_id`、`case_goal?`、`created_at`、`last_at`。现有的 `case` 迁移为 `topic(status=case)`，或保持 `case` 并加 `topic_id` 双向关联，二选一，在 ExecPlan 里决定并写明理由。
- 消息、事实、笔记、情景、塔罗 draw 增加字段 `space_id`、`topic_id`、`space_secondary?`、`route_source`（rule / embedding / model / user / migration）、`route_confidence`。
- 新增迁移：编号按 18 号索引的顺延规则，排在 0009 之后。内容是消息 `(owner, space_id, topic_id, at_ms)` 的表达式索引。
- 新增 API：
  - `GET/POST/PATCH /api/spaces`
  - `GET /api/spaces/{id}/topics`
  - `PATCH /api/topics/{id}`（改名、归档、升级为事项）
  - `POST /api/messages/{id}/route`（改区或改话题，`request_id` 幂等）
  - `GET /api/organize/proposal`
  - `POST /api/organize/apply {batch_id, edits[]}`
  - `POST /api/organize/revert {batch_id}`
- 新工具 `topic_route`（加入 Agent 工具集，每轮都可见）。
- 撤销与删除的级联要覆盖话题摘要与"其他区近况"。
