# 大限、流年与流月

版本：p8-skills-draft-2026-10-18-v2.1；状态：待所有者抽查的解释草稿，不是模型或现实预测验证。

## 方法步骤

1. 先读 horoscope.target_date，再逐层读取 name、ganzhi、index、palace_names、mutagen 与 mutagen_links。当前日期对应层与本命宫名分别保留。
2. 大限提供时间背景，流年/月/日是更细的结构视角；不能因多个层提到同一主题就相乘成“几倍必然”。以实际返回索引关联本命星曜位置。
3. 输出时列明目标日与计算方法。整年四化落宫可供 U2 对照；没有逐日或连续搜索产物，就不声称某段日期是唯一应期。

## 需要的盘面字段

根对象：CalculationArtifact。以下为 JSON Pointer；数组示例索引0仅演示路径，必须按实际对象检索。

- `/data/horoscope/decadal`
- `/data/horoscope/yearly`
- `/data/horoscope/monthly`
- `/data/horoscope/daily`
- `/data/palaces`
- `/data/p8_flying_transformations`：`temporal_layers`保留实际大限/流年/月/日的命宫、宫名和四化，不生成缺层；`matches_named_table`为false时保留差异，不能改写原值。

新增P8接口字段：`/data/p8_time_interactions` 含 `links`、`complete`、`yearly_ganzhi` 与 `target_date`；每条link保存status以及实际本命/流年宫位。缺失或歧义项不能自行补宫位。

## 各流派观点与分歧

虚岁、限起点、流月起法和闰月处理可能有差异，本项目沿用安装版本默认值并保存源码指纹。不把现代包装库默认当作原典唯一解。

只核对已返回的运限，不据模型类声明默认值猜实际年界；安装JS运行配置可能不同。当前字段不等于连续全年扫描，也不参与冻结倒推评分。

## 适用前提

有完整本命与目标日期的运限产物；时刻不准影响命身宫及限层，需保留分支。生日年界与农历/节年界不能凭文字猜换。

## 反例与常见误读

大限不是十年每一天相同；流日出现忌也不能预告现实安全问题。看到某年宫名与本命宫名一样，不等于时间层可以省略。

## 表达示例

“先把十年的背景和这一年的变化分开看〔c1〕。目前只算到这些层，能讨论的重点是结构主题，还不能把具体月份说成事情一定发生的时间。”
